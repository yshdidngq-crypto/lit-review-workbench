# 03 · 配置说明（怎么定这套体系）

字段的类型与必填性见 `01_数据契约.md`。这一份讲**怎么定值**——
分类体系定不好，页面做得再漂亮也没有信息量。

---


## 版式主题与图表配色（V4.9 起可选）

```json
"layout": {
  "theme": "swiss",
  "palette": ["#d93a1f", "#1b4d8f", "#2f6b46", "#8a5a00", "#6b2f6b"]
}
```

- `layout.theme`：留空 = 默认视觉（蓝色系）；`"swiss"` = 瑞士风格主题层
  （`assets/swiss.css`，只覆盖变量与形状，不碰结构类名）。
  无论选哪个，`validate.js` 的开箱检查都照跑，检查项数量不变。
- `layout.palette`：图表序列色，最多十色。不写时瑞士主题给一套十色印刷盘，
  默认视觉沿用原序列色。多个系列容易撞色时优先调这里，不要去改 `charts.js`。

## 一、先定 `topics`：这批文献分几派

### 判据

问三个问题，答案能同时约束住 → 就是一类的边界：

1. 它们**解决的是同一个问题**吗？
2. 换一个方向的人来看，会**把它们放在一起**吗？
3. 它们的方法论有**共同的祖先**（同一篇奠基工作 / 同一条技术路线）吗？

三个都"是"才能合并；否则宁可分细。

### 硬指标

| 指标 | 合理区间 | 越界怎么办 |
|---|---|---|
| 类数 | 4–8 | < 4 说明切太粗，看不出结构；> 8 图例挤成一条线 |
| 最大类占比 | ≤ 45% | 超过就拆开，或把其中一类降级为"其他" |
| 最小类占比 | ≥ 3% | 只有 1–2 篇的，并入"综述与外围" |
| 单类篇数 | ≥ 3 | 否则环形图上是一个看不见的细条 |

最后永远留一类 **「综述与外围」**，兜住弱相关工作。它的颜色用 `#8d9db2`（灰）。

### 两个反面例子

✗ **按年份分**（2020 年之前 / 之后）——这是时间，不是主题。
✗ **按深度学习/传统分**——这是方法类型，应该放 `dl` 字段当筛选维度，不要占主题位。

✓ 正确：按**研究问题**分。配准项目 = 配准与几何对齐 / 融合方法 / 困难场景与匹配歧义 /
评价与基准 / 下游任务集成 / 综述与外围。

### 换一个领域怎么定

若用户做的是「遥感影像变化检测」，主题可以是：
变化检测主干网络 / 样本与标注策略 / 多时相配准与辐射归一化 / 弱变化与小目标 / 评价与数据集 / 综述与外围。
——同样是"问题导向"，不是"技术导向"。

## 二、再定 `stages`：用户项目的流水线

这一维度是**本项目最独特的价值**——它无法从文献里推出来，只能从用户的研究流程里推出来。

定法：让用户用 5 分钟讲一遍"你从拿到原始数据到最后出结果，中间分几步"。
把他口述的每一步写成 `stages` 的一项，控制在 6–12 个。

配准融合项目的例子：

| id | name | desc |
|---|---|---|
| S1 | 预处理与配准候选 | 去噪、增强、初始配准与候选匹配生成 |
| S2 | 特征提取与描述 | 关键点检测、描述子构造、跨模态不变特征 |
| S3 | 匹配与误匹配剔除 | 匹配策略、RANSAC、几何一致性检验 |
| S4 | 变换求解与精化 | 相似/仿射/单应求解与最小二乘精化 |
| S5 | 像素级融合 | 加权、金字塔、显著性引导的像素融合 |
| S6 | 特征级融合 | 特征域对齐与融合策略 |
| S7 | 评价与验证 | 指标选择、真值构造、消融实验 |
| S8 | 下游任务集成 | 检测/分割等任务的联合优化 |
| S9 | 弱纹理与重复纹理处理 | 窗户阵列、周期性结构导致的匹配歧义 |
| S10 | 工程部署与效率 | 实时性、嵌入式部署、模型轻量化 |

注意 S9 和 S10 不是"流程步骤"，而是**贯穿性难题**。允许这样混：只要它能帮用户看出"哪里没人做"。

### 用它做什么

每篇论文标 `stages`，就能算出每个环节的命中篇数。命中 0–2 篇的环节就是**空白点**，
这是最该写进总览页结论的东西——比任何图表都有价值。

```js
const gap = cfg.stages.map(s => ({
  id: s.id, name: s.name,
  n: papers.filter(p => (p.stages || []).indexOf(s.id) >= 0).length,
})).filter(x => x.n <= 2).sort((a, b) => a.n - b.n);
```

## 三、`bands`：评分档位

固定 5 档，`min` 降序，最后一项必须是 0：

```json
[
  { "min": 85, "name": "核心相关", "color": "#c0392b", "action": "优先精读" },
  { "min": 70, "name": "高度相关", "color": "#d97706", "action": "列入必读" },
  { "min": 50, "name": "中度相关", "color": "#2f6feb", "action": "补充理解" },
  { "min": 30, "name": "间接关联", "color": "#6b7d94", "action": "按需阅读" },
  { "min": 0,  "name": "外围相关", "color": "#c3ccda", "action": "暂不优先" }
]
```

`action` 写**动词**（优先精读 / 列入必读），不要写"五星""A 级"这类标签。
颜色必须从七个规范色里取（见 01 文档），且按温度从暖到冷排。

**分档要落在真实分布上**：先统计 `relevance` 的分位数，再定 `min`。
如果全批最高只有 78 分，把第一档定在 85 会导致「核心相关」永远为空。
`demo/config.json` 就是按这个原则定成 `60 / 45 / 35 / 28 / 0` 的（那批样本最高只有 64 分），
原因写在 `demo/README.md` 里，值得看一眼。

判据：定完之后最高档不该是空的、最低档也不该是空的，中间三档大致均匀。

## 四、`presets`：一键筛选

给用户四条最短路径，`id` 建议固定这几个（视图层会按 id 找）：

| id | label | set | 用途 |
|---|---|---|---|
| `core` | 最接近本方向 | `{"relMin":70,"learnMin":60}` | 开题必读 |
| `unread-core` | 高相关未读 | `{"relMin":70,"status":["未阅读"]}` | 今天读什么 |
| `classic` | 传统方法 | `{"dl":["传统方法"]}` | 补基础 |
| `easy` | 入门可读 | `{"diffMax":3,"learnMin":55}` | 刚进组的新人 |

`set` 的键与筛选器字段同名：`q` `topic[]` `year[]` `stage[]` `dl[]` `status[]` `bands[]`
`relMin` `learnMin` `diffMin` `diffMax` `tag`。

## 五、`weights`：优先级公式

```json
"weights": { "relevance": 0.55, "learning": 0.45, "difficulty": 4.0 }
```

`priority = relevance × 0.55 + learning × 0.45 − difficulty × 4`

- 两个 0–1 的权重不要求和为 1，但建议和为 1，便于解释
- `difficulty` 是惩罚项：难度每高 1 级，优先级扣 4 分
- 若用户是刚进组的新人，把 `difficulty` 提到 6–7；若是要写综述的老手，降到 2–3

**改完要在总览页说明公式**，否则用户不知道排序凭什么。

## 六、`extraScores` / `extraTags`：按项目定制

这两个是让工作台"像这个项目专用"的关键。原则：**只有会影响阅读决策的维度才加。**

配准融合项目加了：

```json
"extraScores": [{ "key": "datasetScore", "label": "数据适配度", "high": 75, "mid": 50 }],
"extraTags": [
  { "key": "platform", "label": "采集平台", "order": ["UAV无人机", "地面固定相机", "车载", "未说明"] },
  { "key": "modality", "label": "成像模态", "order": ["RGB可见光", "热红外", "近/短波红外", "未说明"] },
  { "key": "scene", "label": "拍摄场景", "order": ["建筑立面", "城市建筑群", "道路与交通", "未说明"] }
]
```

- `order` 决定筛选器里的排列顺序，**必须以"未说明"结尾**，否则缺失值无处安放
- `extraScores` 每多一个，`db` 页就多一列排序项，别超过 2 个
- 不要加"创新性""写作质量"这种主观维度，评不准反而降低可信度

---

## 七、`lsKey`：必须唯一

```json
"lsKey": "lit-demo-rgbfusion-v1"
```

localStorage 的键。**每个项目必须不同**，否则两个工作台在同一台电脑上打开会互相覆盖阅读状态和笔记。
建议格式：`lit-<项目缩写>-<版本>`。

---

## 八、`detailTabs` 与 `tabs.js` 的对应

`config.detailTabs` 决定标签顺序与显示名，`src/tabs.js` 提供渲染函数。两边 `id` 必须一致：

| id | 显示名 | 渲染内容来源 |
|---|---|---|
| `understand` | 三分钟理解 | `p.overview` |
| `project` | 与本项目的关系 | `p.topicNote` + `p.stages` + `p.relevanceBreakdown` |
| `eval` | 科研评价 | `p.data` + `p.conclusion` + 局限 |
| `guide` | 学习指导 | 前置知识、阅读建议、可复用点 |
| `notes` | 我的笔记 | **固定项，不要改**，由 `app.bind.js` 接管读写 |
| `raw` | 原文摘要 | `p.title` / `authors` / `venue` / `keywords` 原样 |

加标签可以（比如 `"datasets"`），但要同时在 `tabs.js` 里加渲染函数，否则抽屉里是空的。

## 九、配置完成后自检

- [ ] `topics` 4–8 类，最大类 ≤ 45%，有"综述与外围"
- [ ] `stages` 与用户口述的流水线一致，能算出空白点
- [ ] `bands` 五档，`min` 落在真实分位数上，不是拍脑袋
- [ ] `presets` 至少 4 条，`id` 用固定四个
- [ ] `weights` 有明确解释
- [ ] `lsKey` 与别的项目不重复
- [ ] `detailTabs` 与 `tabs.js` 的键一一对应
- [ ] 颜色全部取自七个规范色

## 附录：V3 新增配置字段

### `extScoreWeights`

外部文献六维评分的**默认**权重。页面上的滑块改的是浏览器本地状态，不改这份配置。

```json
"extScoreWeights": { "relevance": 30, "subdirection": 20, "dataScenario": 15,
                     "learning": 15, "evidence": 10, "recency": 10 }
```

权重之和不必等于 100 —— `extTotal()` 会按实际和归一化。所以把某一维调大是"相对更重要"，
不是"把总分往上抬"。

### `extTabs`

外部文献详情抽屉的标签，与 `tabs.js` 里 `window.TABS.extXxx` 一一对应。

```json
"extTabs": [
  { "id": "extAbs",   "label": "摘要原文" },
  { "id": "extWhere", "label": "出处与获取" },
  { "id": "extDir",   "label": "关联方向" },
  { "id": "notes",    "label": "我的笔记" }
]
```

最后一项 `notes` 与本地文献**共用同一个标签函数**，所以外部文献同样能写笔记、标阅读状态。
不要删掉它，也不要改 id。

> V4.5 起 `extWhy`（「为什么推荐」）已删除：外部文献只读过摘要，再挂一栏"为什么推荐"
> 就等于用元数据下结论。`tabs.js` 里也不要再写 `window.TABS.extWhy`。

### `views` 的 V3 四项

`landscape` / `explore` / `external` / `session` 加在 `views` 数组里即可，字段结构与其他视图完全相同
（`id` / `name` / `icon`；`desc` 已废弃，V4.6.1 起不渲染，别写）。`icon` 可省，省略时侧栏显示 `·`。

**顺序按 dash → landscape → map → explore → external → db → cmp → decide → prog → session。**
读者是按"先看全局 → 再看缺口 → 再看机会 → 再补文献"的顺序读的。
