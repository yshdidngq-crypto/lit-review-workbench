# 04 · 校验清单

```bash
node scripts/validate.js "dist/xxx_文献工作台.html"   # 30 项格式与数据
node scripts/smoke.js    "dist/xxx_文献工作台.html"   # 渲染：视图 / 详情标签 / 交互分支各跑一遍
node scripts/test_click.js "dist/xxx_文献工作台.html" # 交互：真机点一下确认筛选生效
node scripts/test_note_export.js "dist/xxx_文献工作台.html"   # 笔记导出：拦截下载，校验文件名与内容
```

退出码 `0` = 全过，`1` = 有未过项，`2` = 本机缺东西（例如 `test_click.js` 找不到浏览器）。**`2` 是"没测"，不是"通过"。**
**有 ✗ 就不许交付。** `!` 是提醒，不阻断，但也要看一眼。

数据齐全时全部通过会输出「结果：通过（30 项检查通过，N 项提醒）」。
`data/` 里缺某个文件时，对应检查没法做，会打 `○` 并单独计数，例如：

```
结果：通过（18 项检查通过、6 项无数据未查，1 项提醒）　共 24 项
说明：○ 那 6 项是因为 data/ 里没有对应数据，本次没查，不代表通过
```

**○ 不是通过。** 它只说明这一项没查，补齐数据重跑一次才算数。
下表按 `validate.js` 的真实执行顺序逐条列出 30 项；第 9 项「数据段」在同一行里给出配置段与论文段两条判据。

> 提醒项（`!`）常见三种：
> ① 正文出现 `TODO` / `待补充` / `PLACEHOLDER` → 交付前必须清掉。
> ② 某个模块"可能未实现" → 视图函数写法不被识别，检查是不是写成了 `const VIEWS = {...}` 而没挂 `window`（这一条现在直接判 ✗，落在第 11 项）。
> ③ 某个模块没有候选算法（如「M2 没有候选算法，页面上会提示去外部补检」）→
>    若这一层本来就不选算法，给它加 `"expectsAlgorithms": false`，这不是消警告，是如实描述。

## 查新页不占校验条目（V4.10）

`data/novelty.json` 与侧栏「查新」一页是**可选模块**，validate 不为它新增检查项：
没有它，数据齐全时 30 项、缺 V3 数据时 24 项；有它也不多一项。
原因是这一页里的数字全部来自外部库（Crossref / arXiv），校验器无法判断它对不对 ——
能做的只有把 5 条 caveat 原样印在页脚，让人知道「查不到 ≠ 没有」。

## 各检查项背后的道理

**1–3 样式基线**：不同人做出来的页面像不像，90% 取决于这十几个颜色和字体。
校验器做的是**精确字符串比对**，不是"看起来差不多"。所以只要看到"颜色变量被改动"，不要去调，
直接把 `base.css` 换回原始文件——因为一定是有人动过它。

**4 结构基线 / 8 脚本注入**：这两项组合起来等价于"你没有手工拼 HTML"。
手工拼出来的页面能打开、能看，但只要少一个 `.card-b` 或者 `bind.js` 提前注入了，
行为就会和别人不一样（比如筛选不生效），而且很难查。所以直接在门禁上拦掉。

**5 离线自包含**（连同 6 禁止项、7 图表规范）：这个工作台是要发给导师、发给组会、拷进 U 盘的。
任何外链在断网或换电脑后都会变成白屏。所以宁可图表少一点，也不许引外部资源。

这条曾经误伤过：早期版本全文搜 `http://`，结果真实文献数据里摘要带的 DOI 链接被当成"外部资源"，
所有带引用的项目一构建就挂。现在的判据只看**会去网络取东西的写法**（`src` / `<link>` / `@import` /
`url()` / `fetch`），`<a href>` 超链接和书目数据里的 URL 不拦——断网时它们只是点不动，页面本身完整。

**9–10 数据段 / 论文数据**：数据错了页面会"看起来正常但数字全错"，这是最危险的失败模式。
所以必填字段、topic 归属、id 唯一性都在构建期和校验期双重拦截。

**13 内容量**：5000 字是个很松的下限（30 篇论文的 `overview` 轻松过万）。
它拦的不是"写得少"，而是"根本没读原文，只抄了标题"。
如果这一项挂了，说明整份产出的价值存疑，必须回去补。

**14 渲染值**：页面上出现 `undefined` 是外行最容易看出来的破绽。
字段名拼错（`p.year` 写成 `p.years`）在 JS 里不报错，只是显示成 `undefined`，所以专门加了这项。

**15–19 V3 数据结构**：这五项都可能打 `○`（无数据未查，不算通过）——只有本地文献的项目同样合法。
但只要提供了数据，就按最严的判据查。其中第 17 项（双向关联）专治一种让读者瞬间失去信任的失败：
方向页说关联 5 篇、外部文献页只标出 3 篇。两个数不一致，整份报告的结论都会被怀疑。

## 交付前三件事

```bash
# 1. 构建（用了 V3 模块的话，build 之前要先跑 landscape.py / link.py）
python scripts/build.py <项目目录>

# 2. 两道门禁，都必须看到「通过」
node scripts/validate.js "<项目目录>/dist/xxx_文献工作台.html"
node scripts/smoke.js    "<项目目录>/dist/xxx_文献工作台.html"

# 3. 人工过一遍（脚本查不出这些）
```

人工检查清单：

- [ ] 双击打开，**断网状态下**图表都能画出来
- [ ] **11 个视图**逐个点一遍，没有一个是"此模块尚未实现"
- [ ] `node scripts/smoke.js <html>` 通过（11 个视图 + 10 个详情标签 + 13 个交互分支 + 1 条编号对照块，含「无算法模块」那条）
- [ ] 点图例/条形，筛选真的生效，计数跟着变
- [ ] 方向树的枝粗看得出来差别（分三档：最粗/中等/最细），节点编号是 1、2、3 与 1.1、1.2
- [ ] 工程实验室换一个**没有候选算法**的模块，五个标签页都能打开（不会出现「渲染失败」）
- [ ] 点任一论文标题，抽屉能打开，六个标签都有内容
- [ ] 笔记打几个字，刷新页面后还在
- [ ] 点「导出笔记 txt」能下载到一份文件，里面有这篇的题录 + 刚才写的笔记
- [ ] 页面上搜不到「建议按四段写」「状态会立即保存」「这批文献是什么、不是什么」这类提示语
- [ ] 研究现状 Q2 的纵轴是环节全名，不是 S1、S2
- [ ] 检索记录页的卡片叫「本次检索不足」，三张卡片右上角没有提示语
- [ ] 右上角切深色主题，文字仍然清晰（不能有黑底黑字）

- [ ] 总览页的篇数 = 用户数据文件夹里的篇数

最后一条最容易被忽略：**数字对不上就是事故**，宁可多花十分钟核对，也不要交出去被导师发现少了 41 篇。
