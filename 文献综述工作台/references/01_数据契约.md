# 01 · 数据契约

三个文件：`config.json`（项目配置）、`data/papers.json`（论文数组）、`data/meta.json`（可选的待审核数据）。
全部 UTF-8 无 BOM，JSON 不允许写注释。

---

## 一、`config.json`

### 必填

| 字段 | 类型 | 说明 |
|---|---|---|
| `project` | object | 见下表 |
| `topics` | array | 一级主题，4–8 类 |
| `views` | array | 固定 10 项（V3 起），`id` 不可改；`lab` 由 build 追加 |
| `detailTabs` / `extTabs` | array | 详情标签；V4.8 起可省略不写，缺项自动用通用标签 |

### `project`

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✓ | 项目全名，用于兜底 |
| `nameLine1` |  | 侧栏 logo 第一行（短，6–8 字） |
| `nameLine2` |  | 侧栏 logo 第二行（4–6 字） |
| `short` | ✓ | 英文/缩写名，决定产出文件名 `<short>_文献工作台.html` |
| `mark` | ✓ | 侧栏徽标文字，1–2 个字符（如 `RF`、`配`） |
| `subtitle` |  | **已废弃**：骨架节点已删，写了也不渲染（V4.6.1） |
| `pageTitle` | ✓ | `<title>`，建议「项目名 · 文献分析学习决策系统」 |
| `dataSource` |  | **已废弃**：骨架节点已删，写了也不渲染（V4.6.1） |

### `topics[]`

```json
{ "id": "T1", "name": "配准与几何对齐", "desc": "一句话界定范围", "color": "#2f6feb" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | `T1`…`T8`。`papers.json` 的 `topic` 必须命中这里 |
| `name` | ✓ | 显示名，4–8 字为宜 |
| `desc` |  | 界定范围的说明，出现在图例提示中 |
| `color` | ✓ | **只能取这七个值之一**：`#2f6feb` `#0e9c9c` `#c0392b` `#d97706` `#6b4bbd` `#8d9db2` `#c47b12` |

### `stages[]`

```json
{ "id": "S1", "name": "预处理与配准候选", "desc": "去噪、增强、初始配准" }
```

技术环节。`id` 用 `S1`…`S12`。**按用户项目的真实流水线切**，不要套用别的项目的环节名。
每篇论文可用 `stages: ["S1","S3"]` 命中多个。

### `bands[]`

```json
{ "min": 85, "name": "核心相关", "color": "#c0392b", "action": "优先精读" }
```

按 `min` 降序排列，最后一项 `min` 必须为 0。`action` 是给用户看的阅读建议动词。

### 其余可选字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `lsKey` | string | localStorage 键名，**每个项目必须不同**，否则同域名下互相串数据 |
| `statuses` | array | 阅读状态枚举，**建议必填**（不写就用默认 6 档，但 V4.9.2 起校验会 ✗：详情页状态按钮靠它渲染）。改动会影响「阅读进度」页 |
| `dlCategories` | array | 方法类型分类名（默认：深度学习核心方法 / 混合方法 / 深度学习辅助方法 / 传统方法 / 无法确定） |
| `dlColors` | object | 上面每个分类对应的颜色 |
| `scoreLabels` | object | 三个主评分的显示名，如 `{"relevance":"项目耦合度"}` |
| `extraScores` | array | 附加评分维度：`{key,label,high,mid}`。会出现在详情页与排序项里 |
| `extraTags` | array | 附加标签维度：`{key,label,order:[...]}`。`order` 里没出现的值显示为「未说明」 |
| `weights` | object | `{relevance,learning,difficulty}` 优先级公式权重，默认 `0.55 / 0.45 / 4.0` |
| `presets` | array | 一键筛选：`{id,label,desc,set:{...}}`。`set` 的键同筛选器字段名 |
| `detailTabs` | array | 详情抽屉标签顺序：`[{id,label}]`，与 `tabs.js` 的键对应 |

### `views[]`（固定 10 项，顺序不可变；`lab` 不写在这里）

```json
{ "id": "dash", "name": "总览仪表板", "desc": "…", "icon": "◧" }
```

| id | 建议 name | icon |
|---|---|---|
| `dash` | 总览仪表板 | ◧ |
| `map` | 技术图谱 | ⬡ |
| `db` | 文献数据库 | ☰ |
| `cmp` | 文献对比 | ⇄ |
| `decide` | 学习决策中心 | ★ |
| `prog` | 阅读进度 | ◔ |

`desc` 已废弃（V4.6.1 起侧栏不再显示悬停提示），写了也不渲染——项目身份写进 `project.overview`。
若某项要额外插到导航末尾，加 `"extra": true`（一般不用）。

## 二、`data/papers.json`

顶层是一个**数组**，元素为论文对象。

### 六个必填字段

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | string | 全局唯一，建议 `E001` / `C001`（英文/中文分开编号） |
| `title` | string | 原文标题，中文文献用中文题名 |
| `topic` | string | 必须等于 `config.topics[].id` 之一 |
| `relevance` | number | 0–100 整数 |
| `learning` | number | 0–100 整数 |
| `difficulty` | number | 1–5 整数 |

> 缺任何一个，`build.py` 直接报错退出。

### 内容字段（强烈建议全填）

| 字段 | 类型 | 说明 |
|---|---|---|
| `titleEn` | string | 英文标题（中文文献时填） |
| `authors` | string | 作者，`;` 分隔 |
| `unit` | string | 第一作者单位 |
| `year` | number | 发表年份。用于年份分布图，**没填就不会出现在图里** |
| `venue` | string | 期刊/会议 |
| `keywords` | string | 关键词，`；` 分隔 |
| `overview` | string | 三分钟理解：出发点 / 提出方法 / 核心机制 / 效果。换行用 `\n` |
| `method` | string | 方法步骤，编号列出，末尾一句概括 |
| `data` | string | 数据与实验：数据集、对比方法、定量结果 |
| `conclusion` | string | 主要结论 / 局限性 / 未来展望 |
| `topicNote` | string | 为什么归到这一类（一句话，避免分类看起来随意） |

> 这四个长文本字段决定详情页是否可看，也决定 `validate.js` 的「内容量」检查能否过（全文中文 ≥ 5000）。

### 结构化字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `dl` | string | 方法类型，取值必须在 `config.dlCategories` 里 |
| `stages` | string[] | 命中哪些技术环节 |
| `failureModes` | string[] | 涉及的失败场景/困难条件 |
| `datasets` | string[] | **有专名**的数据集名（`["USV","UDIS-D"]`）；只有「公共数据集」这类泛称时写 `[]`，泛称不算数据集名 |
| `metrics` | string[] | 评价指标名；没有就 `[]` |
| `hasCode` | boolean | 是否提供代码。**只认出版方明写的 `github.com` 地址**（从摘要/落地页核实），凭印象写不行 |
| `codeUrl` | string | 代码仓库地址；没有就 `""` |
| `tags` | object | 额外标签维度，键同 `config.extraTags[].key`，如 `{"platform":"UAV无人机"}` |
| `extraScores` | object | 附加评分，键同 `config.extraScores[].key`，如 `{"datasetScore":72}` |
| `relevanceBreakdown` | array | 耦合度打分明细：`[{dim,weight,score,reason}]` |
| `mergedIds` | string[] | 若本条合并了重复记录，把被合并的 id 记在这里 |
| `flags` | array | 数据质量标记，如 `["英文标题存疑"]` |

### 三个容易填错的地方（V4.7 实测）

1. **数据集名不要收泛称。**「公共数据集」「无人机数据集」不指明任何一个具体数据集，
   收进来 Q5 的频次表会把泛称当数据集名排序，读者会以为那是几个数据集。
   规则：**带专名的才算**（带拉丁字母的，或中文里人工核过原文的具体名）。
2. **判空值要用精确匹配，不要用前缀。** 曾经用 `^(未|无|不详)` 过滤空值，
   结果「**无人机**可见光航拍序列影像」因为"无人机"以"无"开头被整条丢弃 ——
   一批文献的数据集字段全空，页面报「识别出 0 个数据集」。
   判空值只能拿**确切的空值词**做**全等**比较。
3. **`hasCode` 要有来源。** 走 OpenAlex 逐篇匹配、从摘要里找出版方写的 `github.com`
   地址（见 `scripts/check_code.py` 的做法）；找不到就 `false`，不要猜。

### 空值约定

**禁止**出现 `undefined` / `NaN` / `null` / 空字符串。没有信息就写：

- 文本字段 → `"未报告"` 或 `"无"`
- 数组字段 → `[]` 或 `["未报告"]`
- 数值字段 → 必填项不许空；附加评分可省略该键

`validate.js` 会扫描数据字符串里的 `undefined` / `NaN` 并判失败。

## 二·五、`data/novelty.json`（V4.10 可选，由脚本生成，不要手写）

`python scripts/novelty.py <项目> --draft 方案.md` 的产物。有它，侧栏就多「查新」一页。

| 字段 | 类型 | 说明 |
|---|---|---|
| `generated` | string | 生成时间 |
| `draft` | object | `{chars, head, file}`：方案字数、前 160 字、文件名 |
| `focus` | array | 抽出来的聚焦词（英文），最多 12 个 |
| `queries` | array | 实际发出去的检索式（最多 3 条） |
| `window` | object | `{since, years}`：只查最近 N 年 |
| `sources` | array | `[{name, ok, hits, error}]`：每家源通没通、命中几条 |
| `counts` | object | `{overlap, partial, clear}`：三档各几篇 |
| `candidates` | array | 最多 60 条，见下表 |
| `coverage` | object | `{rawHits, unique, kept}`：原始命中 / 去重后 / 保留几条 |
| `caveat` | array | 5 条边界说明，页面底部原样显示 |

`candidates[]` 每条：`source, id, title, year, venue, doi, url, abstract(前 600 字), score, hitTerms[], titleHits[], risk`。
`risk` 只有三个值：`overlap`（≥70 可能撞车）/ `partial`（≥45 部分重合）/ `clear`（关系不大）。

**这一份不参与校验**：没有它，validate 仍是 24 项（带 lab 30 项）；有它也不会多一项。

## 三、`data/meta.json`（可选）

```json
{
  "generated": "2026-10-29",
  "review": [
    {
      "id": "R01",
      "paperId": "E276",
      "field": "title",
      "problem": "标题开头重复「基于基于」，中英文术语乱序插入，不构成通顺语序。",
      "basis": "源文件标题原文",
      "fix": "基于变分自编码器与红外特征补偿的红外与可见光图像融合"
    }
  ],
  "gaps": [{ "id": "S9", "name": "弱纹理与重复纹理处理", "count": 1 }]
}
```

| 字段 | 说明 |
|---|---|
| `review` | **待审核数据**：解析阶段发现的具体问题，渲染成总览页的「待审核数据」卡片。回答的是「哪几篇有问题、问题在哪个字段」，不是「整体可信度多少」 |
| `review[].id` | 稳定唯一编号。用它记住「已确认」（存在 `localStorage` 的 `reviewDone`），换成随机值会让确认状态全丢 |
| `review[].paperId` | 关联 `papers.json` 的 id，点标题可打开详情。没有对应论文就留空 |
| `review[].field` | `title` / `author` / `year` / `venue` / `doi` / `body` / `duplicate` / `missing` / `pdf`，决定左侧徽章的文字与颜色 |
| `review[].problem` | **必填**。写清楚「哪里不对」，不要写「建议关注」。读者要能据此去核对 |
| `review[].basis` | 可选。判断依据（跟哪个来源比对出来的）。写不出依据就不要下这条结论 |
| `review[].fix` | 可选。建议值。**只显示，不自动应用** —— 改数据必须经过人 |
| `gaps` | 环节薄弱点，`count` 为该环节命中篇数。build.py 不会自动算，需与 `papers.json` 保持一致 |
| `generated` | 生成日期，不填则用当天 |
| `count` | 不填则自动取 `papers.length` |

> 旧的 `quality` 字段（`[[检查项, 结论], ...]` 的笼统统计）已停用。它只能回答「有没有问题」，
> 回答不了「哪几篇、哪个字段」，读的人无法据此做任何核对动作。
> 需要保留汇总信息时，把它写进某条 `review` 的 `problem` 里。

## 四、字段 → 页面映射

改哪个字段会影响哪个页面，方便定位问题：

| 想改的东西 | 改哪里 |
|---|---|
| 主题构成环形图 | `topics` 的 `name`/`color` + 每篇的 `topic` |
| 年份分布横条 | 每篇的 `year` |
| 相关性-难度散点 | `relevance` / `difficulty` / `learning` |
| 技术图谱的环节覆盖 | `stages` |
| 空白点结论 | `meta.gaps` + `stages` 统计 |
| 学习决策的阅读顺序 | `relevance` / `learning` / `difficulty` + `config.weights` |
| 详情页六个标签 | `overview` / `method` / `data` / `conclusion` + `src/tabs.js` |
| 筛选器里多一个维度 | `config.extraTags` + 每篇的 `tags` |

## 附：V3 / V4 新增的数据结构

本文件只覆盖 `config.json` 与 `papers.json`。其余数据各有专门文档：

| 数据结构 | 文件 | 谁生成 | 文档 |
|---|---|---|---|
| ResearchDirection | `data/directions.json` | **你手写** | `07_方向与关联.md` |
| ExternalPaper | `data/external.json` | `discover.py` + `link.py` | `06_外部检索.md` |
| SearchSession | `data/search_session.json` | `discover.py` | `06_外部检索.md` |
| （研究现状报告） | `data/landscape.json` | `landscape.py` | `07_方向与关联.md` |
| ProjectProfile / ProjectModule / AlgorithmOption / LearningUnit / ExperimentPlan / FailureMode / Exercise | `data/lab.json` | **你手写** | `08_科研工程实验室.md` |

**一句话原则：除了 `directions.json` 与 `lab.json`，其余都不是手写的。** 手写 `external.json` 等于手写 DOI 与被引数，
直接违反铁律 7（不得编造 DOI）。`directions.json` 是唯一的例外，因为它是判断而不是抓取。

### 公式字段：写 LaTeX，不要写字形字符（V4.4）

下面这些字段会经过 `rich()` / `richBlocks()`，**写在里面的公式一律用 LaTeX**：

| 字段 | 出现在 |
|---|---|
| `lab.json` → `learning[].levels.math` / `solve` / `numeric` | 原理到工程 |
| `lab.json` → `modules[].mathematicalPrinciple` / `algorithms[].math` | 建模与算法决策 |
| `papers.json` → `method` / `conclusion` | 详情抽屉 |

```json
"math": "齐次坐标下平面点映射写成 $x' \\sim Hx$，其中 $H$ 是 $3\\times3$ 的单应矩阵：\n$$\\begin{bmatrix} x' \\\\ y' \\\\ 1 \\end{bmatrix} \\sim \\begin{bmatrix} h_{11} & h_{12} & h_{13} \\\\ h_{21} & h_{22} & h_{23} \\\\ h_{31} & h_{32} & h_{33} \\end{bmatrix} \\begin{bmatrix} x \\\\ y \\\\ 1 \\end{bmatrix}$$"
```

注意 JSON 里反斜杠要写成 `\\`。**行内 `$…$`、独立 `$$…$$`，不要写成 `\\(` 那种转义形式**——
虽然渲染层也认，但 JSON 里再套一层转义极易出错。写完跑一次 `validate.js`，再截图确认没有 `.mth-err`。
