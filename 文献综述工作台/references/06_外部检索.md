# 06 · 外部文献发现与补检

> 目标不是"多找几篇"，而是回答两个问题：
> **本库之外还有什么？其中哪几篇值得我优先核对？**

---

## 1. 分工：语义给 Agent，确定性给脚本

`scripts/discover.py` 只做四件确定性的事：**检索、归一化、去重、打分**。
检索词必须由你（Agent）根据研究方向生成，通过参数传进去。

这么切的原因很实际：如果让脚本"自己理解主题去扩词"，同一批数据重跑两次会得到两份不同的清单，
报告就没法复核。检索词写死在命令行里，重跑结果一致。

```bash
python scripts/discover.py <项目目录> \
  --en "uav multimodal image registration thermal visible" \
  --en "uav infrared visible image fusion building facade" \
  --en "facade crack detection unmanned aerial vehicle thermography" \
  --zh "无人机 红外 可见光 图像配准" \
  --platform "uav drone aerial unmanned" \
  --object   "building facade concrete bridge masonry crack spall" \
  --scenario "building facade crack defect inspection" \
  --modality "infrared thermal visible rgb" \
  --limit 30 --candidates 50
```

---

## 2. 六个参数各管什么

| 参数 | 作用 | 怎么给 |
|---|---|---|
| `--en`（可重复） | 英文检索词，**按子方向各给一条，3–6 组** | 从你的方向树里逐个子方向翻译，不要一条大而全的句子 |
| `--zh`（可重复） | 中文检索词，补中文期刊覆盖 | 与 `--en` 对应 |
| `--platform` | 平台/载体词（uav / drone / aerial） | 缺失只**软降权**：手持红外的论文方法仍可借鉴 |
| `--object` | 研究对象词（building / facade / concrete / crack） | 完全未命中**硬性排除**：葡萄病害、车辆检测的结论不能迁移到建筑立面 |
| `--scenario` | 应用场景补充词 | 命中率过低时整体降权 |
| `--modality` | 数据模态词 | 参与"数据场景"维度打分 |

**为什么平台和对象要分开？** 两者的失败后果不同：

- 平台不对（手持 vs 无人机）→ 方法仍然可读，只是实验条件不同 → 降权即可
- 对象不对（葡萄园 vs 建筑立面）→ 物理机理、评价口径、缺陷定义全变了 → 结论不可迁移 → 必须排除

合成一个 `--core` 参数就区分不了这两种情况，会把"值得借鉴的手持红外论文"和"完全无关的葡萄病害论文"同等处理。

> `--object` 里的词要**有辨识度**。`structure` 这种词会匹配到 `structural similarity`、
> `infrastructure`，等于没筛。用 `facade` / `masonry` / `spall` / `delamination` 这类具体的。

## 3. 数据源与各自的边界

| 源 | 提供什么 | 不用它做什么 |
|---|---|---|
| **Crossref** | DOI 权威、卷期页码、摘要（部分） | 不带开放获取状态 |
| **OpenAlex** | 被引数、机构、开放获取状态、摘要（倒排索引，本脚本已还原） | 免费额度有限，可能限流 |
| **arXiv** | 预印本与最新工作 | 只覆盖物理/CS/数学，本领域覆盖率天然偏低 |
| **Semantic Scholar** | 被引与引用网络 | 无 key 时经常 429，脚本失败即跳过，不重试 |

OpenAlex 的摘要是倒排索引格式 `{词: [位置…]}`，必须按位置还原成句子。不还原的后果很直接：
整批记录摘要为空 → "证据质量"维度恒为最低档 → 排序失真、对象判断只能靠标题 → 误排除率上升。

`coverageLimitations` 字段会把"哪些源没成功、为什么"写进 `search_session.json`，页面会原样展示。
**不许省略这一段**：只报告结果不报告覆盖范围，等于让读者以为你检索了整个领域。

## 4. 打分：六维加权 + 三道闸门

六维（权重可在页面上调，默认值写死在 `config.extScoreWeights`）：

| 维度 | 权重 | 算什么 |
|---|---|---|
| 相关性 | 30 | 检索词项在「标题+摘要+期刊」中的覆盖率 |
| 子方向匹配 | 20 | 场景词覆盖率与相关性取大者 |
| 数据场景 | 15 | 模态/数据集相关词覆盖率 |
| 学习价值 | 15 | 相关性的一半 + 文献类型（期刊/预印本 vs 其他） |
| 证据质量 | 10 | 有摘要 0.6 + 有 DOI 0.4 |
| 时效 | 10 | ≤2 年 1.0，≤5 年 0.8，≤10 年 0.55，更早 0.35 |

三道硬性排除（不是降权，是直接剔除，理由写进 `excludedSample`）：

1. **撤稿类记录** —— `Retraction Note:` / `Retracted:` / `Erratum` / `Expression of Concern`。
   这类记录有正常 DOI 和标题，只判 `is_retracted` 会漏（OpenAlex 常常还没同步）。
2. **年份晚于当前年** —— 通常是 online-first 的排版年，会让"近两年"统计失真。
3. **相关度 < 25** —— 这类条目能进前列全靠时效分与证据分，内容其实不相关。

两条降权：

- 平台词完全未命中 → 总分 ×0.45；仅部分命中 → ×0.80
- 场景词覆盖率 < 0.15 → ×0.85

多样性上限：单一来源 ≤70%，单一年份 ≤40%。**候选不足时不补位**（宁缺不造）。

## 5. 产出

```
<项目目录>/data/
  external_candidates.json   候选池（默认 50 篇，含全部打分明细）
  external.json              正式推荐（默认 30 篇，由 link.py 补方向关联）
  search_session.json        检索过程记录：查询词、数据源成败、排除/未入选原因、覆盖局限
```

三者都要保留。报告里"为什么这批文献能支撑我的结论"要靠 `search_session.json` 回答，
只交出 `external.json` 等于只给结论不给证据链。

### 5.1 检索漏斗的五个数

`search_session.json` 里有一组数专门用来"把账减平"，页面顶部那排 KPI 就是它们：

| 字段 | 含义 |
|---|---|
| `rawHitCount` | 各数据源返回条数直接相加（含跨源重复） |
| `uniqueHitCount` | 跨源去重后的条数（`duplicateCount` 是被合并掉的条数） |
| `passedScreeningCount` | 过完撤稿/跨年/相关度过低/研究对象不符四道硬门槛后剩下的条数 |
| `candidateCount` | 进入候选池的条数（受 `--candidates` 上限约束） |
| `recommendedCount` | 最终推荐条数 |

它们必须能一跳一跳减通：**原始命中 − 合并 = 去重后；去重后 − 硬性排除 = 过硬筛；过硬筛 → 取前 N 进候选池；候选池 → 多样性上限后得推荐。**
中间少一格，读者自己减出来的数就对不上，会怀疑统计口径；所以宁可多写一个 `passedScreeningCount`，也不要让漏斗断在中间。
旧版记录没有前三个字段时，页面只显示真有的那几跳，**不许拿别的数字顶上**。

## 6. 必须写在页面上的话

这套流程能得出和不能得出的结论，边界很清楚：

**能说**：这几篇的标题与摘要覆盖了我的研究主题，值得优先核对全文。
**不能说**：这几篇证明了某方法更优 / 该方向已被充分研究 / 该方向是空白。
理由：全部判断只基于**元数据与摘要**，没有任何一篇读过全文。

那条边界说明（"只读过摘要"）与每篇的「为什么推荐」标签在 V4.5 已经被删掉了 ——
理由是它们本身也在替读者下判断。所以这条边界现在只能由你自己守：外部文献页只写
"元数据 + 摘要能看出的事实"，不写"这篇证明了什么"。一旦越界，这个页面就从
"检索引擎"变成了"结论生成器"——那是另一种东西，而且不可信。
