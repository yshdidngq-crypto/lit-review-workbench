## 二、网格

```js
grid(2, inner)     // 两栏
grid(3, inner)     // 三栏（最常用：三张分布图并排）
grid(4, inner)     // 四栏（KPI 卡片行）
grid(5, inner)     // 五栏（5 个以内的 KPI）
```

窄屏自动降级为单列，不用你管。**同一行里的卡片高度会拉齐**，所以别在同一行里
放一个环形图 + 一个长表格，会撑出大片留白（正确做法见第五节示例）。

## 三、构件工厂（`assets/ui.js`）

| 函数 | 签名 | 说明 |
|---|---|---|
| `esc` | `esc(s)` | HTML 转义。**所有来自数据的文本都要过一遍** |
| `clamp` | `clamp(v, a, b)` | 夹取 |
| `sum` | `sum(arr)` | 求和 |

## 四、图表引擎（`assets/charts.js`）

全部返回内联 SVG 字符串，直接喂给 `chartBox()`。

| 函数 | 数据形状 | 常用 opt |
|---|---|---|
| `chartStack(data, opt)` | `[{label, parts:[{k, v, c}]}]` | `w`(660) `h`(230) `act` |
| `chartDonut(items, opt)` | `[{k, code, c, v}]` | `thickness`(26) `centerLabel` `act` |
| `chartHBars(items, opt)` | `[{k, v, c}]` | `w`(660) `rowH`(26) `labelW`(150) `unit` `act` |
| `chartScatter(points, opt)` | `[{id, t, tp, rl, df, lv, c}]` | 固定 880×430，无需传 |
| `chartScatterDS(points, opt)` | `[{id, t, tp, x, y, rl, c}]` | 双指标四象限 |
| `chartTreemap(items, opt)` | `[{k, v, c}]` | `w`(640) `h`(296) |
| `chartSankey(sk, opt)` | `{c0:[{k,v}], c1:[{k,v}], c2:[{k,v}], links:[...]}` | `color0/1/2` `nameCol2` `act0/1/2` `w`(900) `h`(400–620) |
| `heatMatrix(rows, cols, getV, opt)` | `rows=[{k}]` `cols=[{k}]` `getV(r,c)=>值` | `corner` `rowAct` `colAct` |

散点字段含义：`rl`=耦合度(0–100) 作 x 轴，`df`=难度(1–5) 作 y 轴，`lv`=学习价值 决定圆点半径，
`c`=颜色，`t`=短标题，`tp`=主题名，`id`=论文 id（点击开详情）。
`chartDonut` 的 `code` 是点击后回传的筛选值（一般填主题 id）。

### 选图规则

- **互斥占比**（主题构成、方法类型）→ `chartDonut`，且只用于单值互斥维度
- **多个标签的分布**（年份、环节、平台）→ `chartHBars`
- **两个连续指标找位置**（耦合度 × 难度）→ `chartScatter`
- **按年看构成变化** → `chartStack`
- **两级交叉看密度**（平台 × 模态）→ `heatMatrix`
- **三级流向**（主题 → 环节 → 下游）→ `chartSankey`
- 一个维度超过 12 项 → 不要画图，用 `table` 或 `progRow` 列表

### 环形图的正确排法

环形图固定 220×220，直接塞进 `grid(2)` 的一栏会撑出大片空白。**必须横排**：

```js
card('主题构成', '按一级主题计，每篇只计一次',
  `<div style="display:flex;gap:14px;align-items:center;flex-wrap:wrap">
     <div style="flex:0 0 200px;max-width:200px">${chartDonut(items, {act:'topic', centerLabel:'篇'})}</div>
     <div style="flex:1;min-width:190px">${items.map(t => progRowDot(t.k, t.c, pct(t.v, n), t.v + ' 篇')).join('')}</div>
   </div>`)
```

## 五、页面节奏（照这个排，别自己发明）

**总览页 `dash`**

1. `grid(4)` 四张 KPI：总篇数 / 核心相关 / 已精读 / 平均难度
2. `grid(2)`：左「主题构成」（环形 + 图例横排）、右「发表年份分布」（横条）
3. `grid(2)`：左「相关档位分布」（progRowDot）、右「方法类型构成」（横条）
4. `cardWide` 关键结论（3–5 条，用 `note()` 区分 info/warn）
5. `cardWide` 数据说明（读 `META.quality`），如实交代局限

**技术图谱 `map`**

1. `grid(3)` 或 `grid(4)`：每个技术环节一张小卡，显示命中篇数 + 代表论文 2–3 篇
2. `cardWide`：环节 × 主题交叉热力（`heatMatrix`）或桑基图（`chartSankey`）
3. `cardWide` 空白点结论（用 `note(..., 'warn')`）

**文献数据库 `db`**

1. 一行工具条（排序 / 形态切换 / 计数）
2. `cardWide` 表格（`table()`），行首列放 `data-act="open"` 的标题
3. 分页条

**文献对比 `cmp`**

- 选中 < 2 篇 → `emptyBox('在「文献数据库」勾选 2–4 篇后回到这里对比')`
- 否则 `cardWide` 表格，**行是维度、列是论文**（维度：问题/方法/数据/指标/结论/局限）

**学习决策中心 `decide`**

1. `cardWide` 推荐阅读顺序（编号列表，每条一段理由）
2. `grid(2)`：左「高相关低难度」散点，右「按主题的入门路径」
3. `cardWide` 前置知识缺口

**阅读进度 `prog`**

1. `grid(4)` KPI：已精读 / 正在读 / 未读 / 已写笔记
2. `cardWide` 进度列表（支持按状态筛选）
3. `cardWide` 笔记汇总 + 导出按钮

## 七、文案规范

- 卡片 `hint` 写**口径说明**，不写形容词。✓「按一级主题计，每篇只计一次」 ✗「精彩的分布」
- 有数值就报数值，不写「较多」「显著」
- 涉及判断的地方给理由：不是「这篇很重要」，而是「唯一同时覆盖弱纹理与配准精化的方法」
- 数据局限必须写出来，放在总览页末尾，用 `note(..., 'warn')`
- 全文不出现「TODO」「待补充」「暂无数据」——校验器会抓
- **V4.6.1（铁律 19）：施工期元数据不上页面**。以下位置在骨架里已删除或禁止，写回即被校验拦截：
  - 页头副标题（config `views[].desc`）——骨架 `#viewSub` 已删，写什么都不会渲染；
  - logo 下副标题（`project.subtitle`）与侧栏底部数据来源 / 生成时间行（`dataSource`）——骨架节点已删；
  - 图下解读灰字（`chartBox` 的 caption）——「右下象限先读」「枝粗＝机会分…」这类图例复述一律不写，
    图例信息要么已在标题 hint 里，要么读者点开节点自己能对上；
  - 步骤口径灰字（三步阅读路径每步下面的筛选口径）与「缺口卡 / 评分权重卡」副题；
  - 页与页之间的导航提示（「每一跳都能在检索记录页核到」这类使用说明不是卡片数据）。
  注意：**注释里也不要原样引用这些被禁短语**——views.js 全文注入 HTML，文案腔调门禁扫的是全文。

### 8.1 新增图表（同样只能用这三个，不许自己写 SVG）

| 函数 | 签名 | 用在哪 |
|---|---|---|
| `chartTree(nodes, opt)` | `nodes = [{id,name,level,parentId,opp,novelty,risk,local,ext,sel}]` | 研究方向树 |

| 通道 | 编码 | 回答什么问题 |
|---|---|---|
| 枝粗 | `opp`（机会分） | 值得投入多少 |
| 枝色 | `novelty`（创新潜力） | 新不新（≥75 红 / ≥60 橙 / ≥45 蓝 / 其余灰） |
| 节点高 | `local`（本库支撑篇数） | 有没有底子 |
| 边框 | `risk`（风险） | 会不会做不出来（越厚越高，≥70 加虚线） |

叶子再多也**不要换成散点图**：散点丢掉父子包含关系，而方向天然是树。

### 8.4 版式约束（V3 页面容易踩）

- 方向树必须**通栏**（`cardWide`），半栏宽度下两级节点会挤在一起
- `explore` 页用 `grid-template-columns: 1fr 1.12fr` 两栏，左清单右详情；不要用 `grid(2)`
  ——右侧详情文字多，等宽会让左侧出现大片空白
- **卡片里的格子要刚好排满**。KPI 卡数量与 `grid(n)` 的 n 必须一致：5 张卡配 `grid(5)`，
  否则末行会空出格子（`.g5` 的折行断点在 1280px，1500px 窗口下是 5 列）。
  六维网格同理：`加权总分` 不是维度，别塞进六维网格凑第 7 格——它会挤掉"证据质量"，
  而且页面根本看不出少了一维。总分的正确位置是标题右侧的 `.etot` 徽标
- 两张并排的表格（如排除样例）要评估标题列宽：半栏下英文标题会被压到 40 字，
  宁可改成两张通栏卡片叠放
- `landscape` 页八问（Q1–Q8 连续编号）按两两成对排：Q1/Q2、Q3/Q4、Q5/Q6、Q7/Q8
- `external` 页每张卡固定 6 个数字（加权总分/相关度/子方向/数据场景/学习价值/时效），
  用 3×2 网格，不要因为某篇缺字段就少一格

## 十、V4.1 新增：两个总览页构件

### 10.1 档位横排 `.bandgrid` / `.bandcell`

原来「与本方向的相关程度」用竖排进度条，与右侧长卡片并排时高度差三倍，左卡下方空出一大块。
改成横排五格（宽屏自动 `auto-fit` 到一行，窄屏折行）：

```
┌──────────┬──────────┬──────────┐
│ 核心相关  │ 高度相关  │ 中度相关  │
│    5     │    3     │    9     │
│  ≥ 60    │  ≥ 45    │  ≥ 35    │
└──────────┴──────────┴──────────┘
```

- 数字用档位色（`bands[].color`），标签与阈值用 muted
- **阈值写进格子**，不再用 `note()` 在卡片下方解释一遍——同一句话说两次会让人怀疑还有别的规则
- 位于 `cardWide` 内，不要用 `grid(2)` 包，否则又回到高度失衡

### 10.2 待审核数据 `.rev`

左徽章标示**问题字段**（标题/作者/年份/期刊/DOI/正文/重复/缺字段/无全文），右侧是人工「确认」。
一条一行，行高随内容自适应——**不要固定高度**，问题描述被截断就看不出错在哪，这块就白做了。

| 元素 | 规则 |
|---|---|
| `.rev` | `max-width:980px`。整行宽度下正文每行太长反而难读，按钮也会离正文太远 |
| `.rev.on` | 已确认：`opacity:.5`，按钮变成填充绿底白字「已确认」 |
| `.rev-tag` | 颜色取 `REVIEW_FIELD[field][1]`，边框同色，白底透明填充 |
| `.rev-link` | 论文标题可点（`data-act="open"`），悬停下划虚线 |
| `.rev-src` | 「依据：… ｜ 建议：…」一行，muted。**建议值只显示不自动应用** |

确认动作走 `data-act="obj-flip"` + `data-k="reviewDone"` + `data-id="<问题id>"`，
状态存 `localStorage`，不写回 `meta.json`。

### 10.3 允许留空的头部文案

`project.subtitle` 与 `project.dataSource` 可以为空字符串，`base.css` 里有
`.logo p:empty,.side-foot>div:empty{display:none}` 兜底，不会留一段空白。
页头 `views[].desc` 为空时同样不渲染副标题。

这条是为了配合铁律 13：**写不出有信息量的一句话，就留空**，不要写「可以把这里理解：研究选题」。

## 十一、编号对照块 `.sidmap`（V4.2 置顶，V4.4 改为吸附 + 可拖动）

技术图谱页有三处用 S1…S10 当标签：左侧条形图的行、`heatMatrix` 的行头、`论文 × 环节` 表的列头。
编号本身不含语义，读者看到 `S7` 无法知道那是「RANSAC 与最小二乘精化」。
**对照必须置顶且用红色**，压在图注或表格末尾不算——读者那时已经先困惑过一次。

置顶只解决第一屏。这一页很长，往下滚到矩阵中段时对照已经出画，读者要么往回翻、要么放弃。
所以 V4.4 把它改成**吸附在视口顶部 + 可拖动**：

```
⠿ 编号对照：本页 S1—S10 指下列技术环节，下方三张图同此编号        [收起] [钉回]
─────────────────────────────────────────────────────────────────────────────
S1  数据准备与跨模态预处理      S2  局部特征检测与描述    S3  跨模态特征匹配
S4  初始配准与几何候选生成      S5  变换模型估计          S6  几何先验与候选筛选
…（逐条列全，不许截断）
```

| 元素 | 规则 |
|---|---|
| `.sidmap` | 边框与标题用 `var(--bad)`；`position:sticky;top:0;z-index:30`。底色必须**不透明**：`linear-gradient(rgba(192,57,43,.045),…)` 叠在 `var(--panel)` 上，深色主题 `.1` |
| `.sidmap-bar` | 一行三段：拖动柄 / 标题 / 按钮组 |
| `.sidmap-grip` | `⠿`，`cursor:grab`，`touch-action:none`（否则触屏拖动会变成页面滚动） |
| `.sidmap-acts` | 「收起」切换 `.folded`；「钉回」只在浮动态显示（`[data-mode="float"]` 时才 `display:inline-block`） |
| `.sidmap-g` | `auto-fit,minmax(300px,1fr)`，宽屏 3–4 列，窄屏自动折行；`.folded` 时 `display:none` |
| `.sidmap-i b` | 编号固定 26px，红色加粗，便于与右侧全名对齐扫读 |
| `.sidmap-i span` | **禁止 `text-overflow:ellipsis`**。环节名被截成「数据准备与跨模态预…」等于没标注 |
| `.sidmap-ph` | 拖走后原位的虚线占位块，高度＝原块高度，防止下方图表整体上跳 |
| `.sidrows` | 给同一页的 `progRow` 用，把标签列从 150px 放宽到 188px，容下 `S1　全名` |

拖动行为（`ui.js` 的 `mountPins`，挂在 `window.AFTER_RENDER` 上，每次渲染后重新装）：

- 指针按下拖动柄 → 若还在吸附态，先切成 `position:fixed` 并把当前 `getBoundingClientRect()` 写进 `left/top`，
  同时在原位插入 `.sidmap-ph`。
- 拖动中把 `left/top` 夹在视口内（留 6px 边距），松开时把位置记进 `PIN_POS[key]`。
- 切走页面再回来仍停在原处（位置只存在内存里，不写 `localStorage`——它是视图状态，不是用户数据）。
- `Esc` 或「钉回」回到吸附态；窗口缩放时重新夹一次坐标，避免落到画外。

**顶部留白的来源**：`.view` 的 `padding-top` 已改成 0，改由 `.view>:first-child{margin-top:18px}` 提供。
不这么改的话，吸附块贴在滚动口上沿时，它上方会漏出一条 18px 的正文。

产出条件：`validate.js` 第 28 项同时要求 `class="sidmap"`、`data-pin`、`.sidmap{…position:sticky…}`；
`smoke.js` 另有一条「由 sidLegend 生成（吸附 + 拖动柄 + 钉回）」。
视图层调用 `sidLegend(stages, {key:'map', suffix:'下方三张图同此编号'})`，**不要手写静态块**。

## 十二、V4.3 修订：方向树的枝粗与编号

`chartTree` 有三个通道：枝粗＝机会分、枝色＝创新潜力、块高＝本库支撑、边框＝风险。
V4.3 修了两个让通道失效的问题。

### 12.1 枝粗必须做本批内归一化

原来按 `1 + opp/100*6` 算宽度。机会分实际落在 50–85，换算出来只有 4.2–6.1px，
四舍五入到 .1 之后肉眼就是"一样粗"——枝粗这个通道等于没画。

改成按本批 `min…max` 映射到 **2–11px**：

```
t = (opp - oMin) / (oMax - oMin)      // 本批内相对位置
width = 2 + t * 9
```

代价是宽度只在本批内可比，所以图注必须写「本批内相对比较（最粗的是本批最高分，不是满分）」。
**没有这句，读者会以为最粗＝满分。**

### 12.2 两列之间要留出"树枝"的长度

`colX = [16, 496]`、`colW = [416, 372]` → 列间 64px。
原来列间只有 12px，连线只剩一个小钩子，粗细差异根本没地方显示。

### 12.3 节点编号用父子式

左列 `1 2 3`，右列 `1.1 1.2 2.1 …`。**不要用 1..9 的顺序号** ——
顺序号会把左列打成 1、4、7，读者以为中间漏了节点。
编号画在方块内左上角（10px，取枝色、85% 不透明度），标题左移让出 18px。

### 12.4 父方向缺失的节点也要画

`parentId` 指向不存在的 id 时，原来的布点循环永远不会给这个节点定坐标，
它就静默消失。现在把它们补到最后一行单独列出 —— 少一个方块，读者只会觉得页面出错。

## 十三、V4.4 新增：公式排版（KaTeX 全内联）

「原理到工程」页里全是推导：单应矩阵、相位一致性、RANSAC 迭代次数、融合权重。
这些内容用文字写不清楚，用 Unicode 字符硬拼又必然散架（`H⁻¹` 打不出来，`ĥ` 更打不出来）。
V4.4 起全站公式走 LaTeX，由 `assets/katex.min.js` 排版。

### 13.1 三条链路，缺一不可

| 层 | 文件 | 干什么 |
|---|---|---|
| 样式 | `assets/katex.css` | KaTeX 的排版规则，20 个 woff2 字体全部转成 `data:font/woff2;base64,…`（约 304 KB），保证断网可排版 |
| 引擎 | `assets/katex.min.js` | `window.katex.renderToString(tex, {displayMode, throwOnError, strict:false, output:'html'})` |
| 调用 | `assets/ui.js` 的 `rich()` / `richBlocks()` / `texHTML()` | 在**字符串层**把 `$…$`、`$$…$$`、`\(…\)`、`\[…\]` 切出来，交给 KaTeX |

`math.js` 只是兜底：它扫 `#view` 与 `#drawerBody` 的文本节点，处理那些没经过 `rich()` 的路径
（抽屉里临时拼的字符串、第三方的 innerHTML）。它**不能**当主力——原因见下。

### 13.2 必须在字符串层切分，这是硬约束

`rich()` 的顺序是：**先切公式 → 再 esc → 再 `**加粗**` → 再 `\n`→`<br>`**。

如果反过来先把 `\n` 变成 `<br>`，一段写成

```
$$
\mathrm{PC}(x)=\frac{\sum_i w_i\cos(\phi_i(x)-\bar\phi)}{\sum_i w_i}
$$
```

的公式就被拆进四五个文本节点，DOM 层的 `math.js` 按节点匹配再也配不到 `$$…$$`，
页面于是把 `\frac`、`\mathrm` 原样摊在正文里。**V4.3 就是这个 bug**，截图里看得清清楚楚。


```js
function lbRich(s) { return richBlocks(s); }
```

### 13.3 写法约定

| 场景 | 写法 |
|---|---|
| 行内符号 | `$H$`、`$3\times3$`、`$\lVert h\rVert=1$` |
| 独立公式 | `$$…$$`，前后空行；`.mth-d` 自带 `display:block` 与横向滚动 |
| 多行推导 | `$$\begin{aligned} a &= b \\ c &= d \end{aligned}$$` |
| 矩阵 | `\begin{bmatrix} h_{11} & h_{12} & h_{13} \\ … \end{bmatrix}` |
| 函数名 | `\mathrm{PC}(x)`、`\operatorname{rank}(H)`；直接写 `PC(x)` 会排成 P·C·x 三个斜体变量相乘 |
| 转置 / 估计量 | `H^\top`、`\hat{x}`、`\tilde{p}` |
| 文本混排 | 公式里要写中文时用 `\text{约束}`，不要直接塞汉字 |

**禁止**：`x′`、`σ²`、`√`、`∑`、`≈`、`≤` 这类 Unicode 硬拼（基线不齐、只有寥寥几个上标可用）；
页面上出现 `\frac`、`\mathrm`、`$$` 字样（＝渲染失败）。

### 13.4 渲染失败的可见反馈

`texHTML()` 里 `throwOnError: true`。解析失败时不静默吞掉，而是输出 `.mth-err`：红色、保留原文、
`title` 里带 KaTeX 的报错句子。这样生成方能一眼看见哪条公式写错了，
而不是让读者对着一块空白猜。

### 13.5 体积代价

KaTeX 让产物从 0.73 MB 涨到 1.37 MB。这个代价是买"断网、单文件、公式可读"，
与 Skill 的核心约束一致；相比之下 CDN 引入会让整个文件在无网环境下变成一堆 TeX 源码。
**不要改成外链。**
