## V4.12.3（2026-11-02）两处门禁修补

**为什么改**：一次外部改版（codex）提了两条真问题，我核过后收下，但把其中一条的处置改了。

- `validate.js`「双向关联」：外部文献与方向**都非空、却一篇都没挂方向**时，
  以前判 `ok`（两侧都是空集，对称就算一致——这是假通过）。
  现在单独提示：`0 / N 篇挂了方向`。
  **只提醒、不判失败**：要不要把外部文献挂到方向上是项目自己的选择，
  不能因为没挂就挡交付；但要求交付说明里写明"未与方向关联"。
- `test_note_export.js`：浏览器起不来时抛 Node 堆栈、靠退出码猜结果；
  现在打一句人话、**退出码 2 = 没测**（与 `test_click.js` 同一套约定）。
- 检查项总数不变（无 lab 24 项 / 带 lab 30 项）。

**没采纳的**：把"0 关联"判成 `bad`。实测在 174 篇的真实项目上会把原本能交付的产物判红，
且原文案「两侧空集合相等」与实际（两侧都非空）不符。

**为什么改**：这三件事都不是功能缺失，是配置或渲染漏了一步，但用户看到的是

## V4.11.1

**修「研究现状 Q1 的环形图整张一个颜色」。**

为什么改：`data/landscape.json` 里每一行的 `color` 是空串时，视图层的兜底写的是
`r.color || 'var(--accent)'` —— 六个扇区全拿到同一个强调色，饼图变成一坨，分类维度
整个消失。你那份数据的 `landscape.json` 生成于「主题还没配色」的时候，所以只有它是
坏的；配置里六个主题其实都有颜色。

四处改动：

- `assets/views.base.js`：兜底改成 `c: r.color || seriesColor(i)`（图例圆点同样），
  即使数据没配色也按色板位取色，不会再退化成单色；
- `scripts/landscape.py`：生成 Q1 时若主题没写颜色，按主题顺序取默认色板，新生成的
  `landscape.json` 天生带颜色；
- `scripts/validate.js`：「主题配色」加一条提醒 —— 环形题（`chart: "donut"`）的
  `rows` 若 **全部** 没有 `color`，提示 "像是早于配色的旧文件，重跑 landscape.py"。
  只查环形题（Q1/Q8），不碰柱状与时间线那种单序列图；不新增检查条目，总数仍 30。
- 实测：demo 30 项通过 / 1 提醒；他的 174 篇项目 24 项通过，Q1 六个扇区六种颜色。

## V4.11.0

**通用骨架换成原 demo 的那一版，并拆出 `assets/tabs.base.js`。**

为什么改：V4.8 的 `assets/views.base.js` 是我另写的一版简装通用骨架，跟 demo 的
手写版**版式完全不同**。项目只要没写 `src/views.js`（或者只写了 dash 一页），其余
页面就落到那版简装骨架上 —— 用户看到的是「功能丢了、排版全错、跟演示站不是同一个
东西」。同学实测反馈就是这么来的。

现在：

- `assets/views.base.js` = 原 demo 手写视图层（实测零项目专有词，可以安全当底座），
  十一页：dash / landscape / map / explore / novelty / external / db / cmp / decide /
  prog / session；
- `assets/tabs.base.js` = 原 demo 手写详情标签，九个：understand / project / eval /
  guide / notes / raw / extAbs / extWhere / extDir；
- 两个底座与项目层**各自包进 IIFE**：过去项目是从 demo 抄 `views.js` 的，顶层
  `const REVIEW_FIELD` / `function topicName` 会和底座重名，直接 `Identifier already
  declared` 崩掉；隔离之后各写各的，互不干扰；
- `accessLabel()` 上移到 `assets/ui.js`：它原来只定义在 tabs.js 里，视图层靠「同一个
  全局作用域」才借得到，隔离后就借不到了（会报 `accessLabel is not defined`）；
- `demo/` 不再保留 `src/views.js` 与 `src/tabs.js`：内容已整体提升为底座，留着等于
  双份注入。demo 构建日志现在写「项目自己写 0 个，通用骨架 12 个」。

升级后：任何项目重新 `python scripts/build.py <项目目录>` 一次，页面就和 demo 一样了。

## V4.10

**新增：查新（`scripts/novelty.py` + 侧栏「查新」页）。** 由同学的真实需求触发：
"我已经写了一部分，帮我看看别人是不是做过，别让我白做"。

  `app.core.js` 导出 `NOVELTY`；`views.base.js` 加 `BASE.novelty`（三个 KPI + 表格 + 边界说明）。
- 实测：demo（8 个聚焦词，91 条去重）→ 1 撞车 / 8 部分 / 51 关系不大；
  他的 174 篇项目（6 个聚焦词，110 条去重）→ 3 撞车 / 25 部分 / 32 关系不大，侧栏 11 格，

## V4.9.2

**修一个「点了没反应」的真 bug：阅读状态改不了。**

症状：读完一篇，回到列表还是「未阅读」。不是你没点对，是页面上根本没有能改的地方。

三个成因一起修：

1. `config.json` 没配 `statuses` 时，详情页「阅读状态」按钮组是**空的**——`tabs.js` 只读 `cfg.statuses`，
   没配就是零个按钮。现在回落到默认 6 档。
2. 数据库页的状态只显示文字，不能点。现在那一格是按钮，点一下进下一档
   （`statusTag()` 改成 `<button class="tag" data-act="status-next">`）。
3. 抽屉里点完状态不重画，看着像没变。`status-set` / `status-next` 现在会刷新当前详情标签。

门禁：第 9 项「数据段」新增 `statuses` 检查，缺失或为空直接 ✗。**不新增检查条目，总数仍 30。**

## V4.8.3 — 2026-11-01

> 从同类 skill 偷了两条真正有用的东西：**DOI 要问注册中心**，**禁令要点名病灶**。

### 新增
- `scripts/doi_check.py`：拿每个 DOI 去问 Crossref，查不到的再走 `doi.org` 解析服务
  （arXiv 的 `10.48550/*` 注册在 DataCite，Crossref 一律 404 —— 只查一家会把真论文误判成假 DOI）。
  四种结果分开报：已注册 / 题名对不上（多半套错了 DOI）/ 查无此 DOI / 未核验（网络失败，不算通过）。
  退出码 0 干净、1 有问题、2 被限流。实测 demo：27 条 DOI 全部已注册；塞一条假 DOI 立刻报 ✗。
- `SKILL.md` §4.1「反面清单」：把"不编造/不旁白"换成点名病灶的八条（给每篇写摘要、
  首先然后最后、效果写形容词、摘要当全文、本库没有当没人做过、方向配形容词、
  施工期信息上页面、自我评价）。
- `SKILL.md` §8 交付自检新增一条：`doi_check.py` 退出码 0；§9 目录补 `doi_check.py`。

### 为什么
`link.py` 只做字段配对，从不问"这个 DOI 存在吗"。而一个手抄错的 DOI 在页面上
安静地挂着、点开 404，整页看起来毫无异常 —— 这是最难被肉眼发现的错。

### 修复
- **`pdf2md.py` 双栏阅读顺序**：页面内排序原来只按 `y` 坐标，把栏号 `gi` 丢掉了。
  双栏论文里右栏 `y` 略小的行会插到左栏前面，整页变成按行交错——文本读起来仍然通顺，
  字数统计也正常，所以肉眼和门禁都发现不了。现在排序键改为 `(栏号, y)`，表格也补了栏号。
  实测：一页左右各 8 行、`y` 故意错开 15pt，修复前顺序是 `L0 R0 L1 R1 …`，
  修复后是 `L0…L7 R0…R7`。
- **`landscape.py` Q4 头条句**：原来写死「…；传统方法 %d 篇；…」，当篇数最多的一类
  本身就是「传统方法」时，会印出「传统方法 5 篇；传统方法 5 篇」。现在按实际第一名分两支：
  第一名是传统方法时说「传统方法 5 篇（xx.x%），是本批篇数最多的一类；其余派别合计 N 篇」，
  否则保持原句式。
- **生成的文件统一用 LF 换行**：脚本原来用文本模式写 `data/*.json` 与产物 HTML，
  Windows 上会被自动翻成 CRLF，于是同一份数据在不同系统上生成的文件字节不同——
  git 里表现为整个文件都被改动，`换人换机器产出一样` 也只覆盖内容、不覆盖字节。
  现在 12 处写入点显式写 `newline="\n"`。副作用：`demo/data/landscape.json` 重新生成后，
  顺带把 7 处早于生成器的旧措辞（「未报告数据集」→「本次未抽到数据集」等）对齐到当前版本。

## V4.8.0 — 2026-11-01

> 这一版动的是架构：**内容层从「必须重写」变成「可选覆盖」**。

### 新增
- **`assets/views.base.js`（锁死）**：十个内置页面 + 九个详情标签的通用实现，
  只读 `config.json` 与 `data/`，不含项目特有措辞。与 base.css / charts.js 同级锁定。
- `examples/data_only/`：零代码示例。只有 config + data，没有 `src/`，
  validate「23 项通过、1 项无数据未查」、smoke「全部通过」。

### 改动
- `build.py`：注入顺序加入 `views.base.js`（在 `src/views.js` 之前），
  收尾用 `Object.assign` 合并 —— 项目写过的覆盖同名项，没写的用通用版。
- `build.py`：`src/views.js` 与 `src/tabs.js` 改为**可选**。缺文件不再让构建失败；
  但「文件存在却没导出 window.VIEWS / window.TABS」仍然直接失败（那是写错了，不是选择不写）。
- `build.py`：构建日志新增「内容层来源」，说明这一版有几个页面是项目自己写的、几个用通用版。
- `validate.js`：视图层与详情页的失败提示同时给出「写 src/views.js」与「用通用骨架」两条路。

### 为什么
改之前，每个项目都要重新生成约 1,240 行 / 72 KB 的 `views.js`，其中九成是跨项目一模一样的
拼装代码（KPI 行、chartDonut/chartHBars、card/grid/table 调用）。以 `demo/src/views.js:126-223`
的 `window.VIEWS.dash` 为例，98 行里项目特有文字只有五六个字符串。代价是三项：
①每个项目的生成成本约 25k tokens 输出；②历史上所有版式 bug（年份 k/val、`L is not defined`、
六维网格挤爆）都长在这一层，因为它是唯一可自由改写的；③「产出完全一致」的承诺只覆盖 CSS 与图表，
不覆盖版式拼装。现在这一层锁死，一致性才真的说到做到，bug 也只需要修一次。

## V4.7.0 — 2026-11-01

### 新增
- **变更记录（本文件）**：随包发布，版本差异一眼可见。
- **工程实验室改为「用户自选」**：不再因为 `data/lab.json` 存在就自动加进侧栏。
  三种启用方式任选其一：命令行 `--with-lab`、`config.json` 里 `"features": {"lab": true}`、

  替用户做决定是不合适的 —— 所以改成让用户自己选。
