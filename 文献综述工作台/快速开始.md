# 快速开始

这是给**人**看的说明。给 WorkBuddy 看的规范在 `SKILL.md`。

目标：组里每个人做完文献整理，产出的 HTML 长得一模一样。
做法不是"统一风格口头约定"，而是**共用同一套锁死的样式与引擎文件**。

---

## 一、装一次，以后都能用（推荐）

1. 把 `文献综述工作台` 整个文件夹，放到：

   - Windows：`C:\Users\<你的用户名>\.workbuddy\skills\`
   - macOS / Linux：`~/.workbuddy/skills/`

   放好后的路径应该长这样：
   `C:\Users\<你>\.workbuddy\skills\文献综述工作台\SKILL.md`

2. 重启 WorkBuddy（或在设置里刷新一下 Skill 列表）。

3. 新开一个对话，直接说：

   > 帮我整理这批文献。我的方向是「无人机红外与可见光图像配准融合，做建筑缺陷检测」，
   > 现在要写开题报告，得先搞清楚哪些是必读、哪些环节还没人做。
   > 论文数据在 `D:\我的文献\rgb-t` 这个文件夹里。

   它会自动按 `SKILL.md` 的流程走。

---

## 二、只用一次（不装 Skill）

新开一个 WorkBuddy 对话，把 `SKILL.md` **全文**粘贴进去，然后紧接着写你那三句话：

> 我的项目是：……
> 现在的需求是：……
> 论文数据文件夹：`D:\……`

产出与方式一完全一致。

## 三、前置条件

| 依赖 | 用途 | 必需 |
|---|---|---|
| WorkBuddy | 干活 | ✓ |
| Python 3.8+ | 跑 `scripts/build.py` 拼装 HTML | ✓ |
| Node.js 14+ | 跑 `scripts/validate.js` / `smoke.js` 做门禁 | ✓（**必装**：校验是强制步骤，缺了没法验证一致性） |

检查一下：

```bash
python --version
node --version
```

Windows 上 `python` 不通就试 `py -3`，macOS / Linux 用 `python3`。
**三个校验脚本（`validate.js` / `smoke.js` / `test_click.js`）不需要 `npm install`**——零依赖，只要 Node。
Python 侧只有 `pdf2md.py`（PDF 转 Markdown）需要**一个**第三方库：

```bash
python -m pip install pymupdf
```

只处理已有的 `papers.json`、不碰 PDF 的话，不用装。

## 五、做自己的项目

三层结构，照 `demo/` 抄：

```
我的项目/
├── config.json            ← 复制 examples/config.example.json 改内容
├── data/
│   ├── papers.json        ← 每篇论文一条，六个必填字段
│   └── meta.json          ← 可选，写数据质量声明
└── src/                   ← 可选，整个文件夹都可以不要
    ├── views.js           ← 想覆盖某一页才写，不用抄十页
    └── tabs.js            ← 同上
```

**V4.8 起 `src/` 可以不存在。** 十个页面与九个详情标签都有通用版（`assets/views.base.js`），
只放 `config.json` + `data/papers.json` 就能出完整页面，`validate.js` 与 `smoke.js` 照样全绿。
想加项目自己的判断，就只覆盖需要改的那一页：

```js
window.VIEWS = {
  decide: function (papers, cfg) { return '……你自己的阅读顺序页……'; },
};
```

没写的自动用通用版（合并是 `Object.assign`，不是整体替换）。
例子：`examples/data_only/` 一行代码都没有，可以先跑它看看通用版长什么样。

顺序建议：

1. 先只做 `papers.json` 的前六个字段（id/title/topic/relevance/learning/difficulty），
   跑一次 build + validate，确认能出页面（此时详情页是空的，但主界面已经能看）
2. 再补 `overview` / `method` / `data` / `conclusion` 四个长文本，
   这时详情页才有内容，validate 的「内容量」检查才会过
3. 最后按自己的研究方向调 `views.js` 里的文字判断（空白点、阅读顺序、前置知识）

> 实际上你不用手写这四步——让 WorkBuddy 按 `SKILL.md` 帮你做，你只需要检查它给的分类和评分对不对。

## 六、为什么必须是这套文件

`assets/` 里的这些文件是**锁死**的（`build.py` 只认它们）：

- `base.css`：配色、圆角、间距、字体栈 —— 页面的"长相"全在这
- `charts.js`：所有 SVG 图表（环形、堆叠、横条、散点、树图、桑基、热力）的绘图代码
- `ui.js`：卡片、KPI、表格、标签、进度条的构件工厂 + 公式渲染（`rich()`）
- `app.core.js`：筛选、排序、路由、抽屉、主题、导出
- `app.bind.js`：所有点击交互
- `katex.min.js` / `katex.css`：公式排版引擎（全内联，字体已转 base64）
- `math.js` / `math.css`：公式的兜底渲染与容器样式

`build.py` 只从 Skill 自己的 `assets/` 读这些文件，**不读你项目目录里的同名文件**。
所以就算有人在项目里改了 `base.css`，也不会生效——这正是"换台电脑也一模一样"的技术保证。

`validate.js` 是配套的检查工具，它逐项比对颜色变量、字体栈、骨架类名、脚本注入顺序、
数据完整性。**过不了就是格式跑偏了，不许交付。**

## 七、常见问题

**Q：我改了 `assets/base.css` 想换个主色，可以吗？**
只允许改 `--brand` / `--accent` / `--accent2` 三个值，且改完整组都得跟着改，
否则你的产出和别人的对不上（`validate.js` 会报"颜色变量被改动"）。默认别动。

**Q：页面打开一片空白？**
按 F12 看 Console。最常见两种：
① `views.js` 里写成了 `const VIEWS = {...}`，必须挂到 `window.VIEWS`；
② `tabs.js` 里某个标签的 `render` 抛错（通常是访问了不存在的字段）。

**Q：点图例没反应？**
视图层里写了 `onclick` 或 `addEventListener`。改成 `data-act` + `data-val`，由 `app.bind.js` 统一接管。

**Q：页面上出现 `\frac`、`$$`、`\mathrm` 这些源码？**
说明那处的公式没经过 `ui.js` 的 `rich()` / `richBlocks()`，而是被 `esc()` 直接转义了。
自己拼 HTML 时把 `esc(x)` 换成 `rich(x)`（或 `lbRich(x)`）；**不要**在 `rich()` 之前做
`\n` → `<br>`，那样公式会被拆散，谁都渲染不了。详见 `02_视觉规范.md` 第 13 节。

**Q：笔记能导出来吗？换了电脑还在吗？**
笔记存在浏览器的 localStorage 里，刷新、关页面都还在，但**清缓存、换电脑、重装浏览器会丢**。
所以「我的笔记」里有一个「导出笔记 txt」按钮，导出的是这一篇的题录（编号/标题/作者/
年份/出处/DOI/关键词/主题/环节/评分）+ 阅读状态 + 你的笔记，文件名形如
`笔记_E276_标题前24字.txt`。导出前会自动把你刚写但还没保存的内容一起存进去。
要整表导出用「阅读进度」页的 CSV 或「文献数据库」的导出。

**Q：技术图谱页的 S 编号对照块能不能跟着滚动？**
默认就吸附在视口顶部（`position:sticky`），按住左上角 `⠿` 可以拖到任意位置，
点「钉回」复位、点「收起」只留标题行。它是 `ui.js` 的 `sidLegend()` 提供的，
视图层直接调用即可，不要自己手写 `<div class="sidmap">`。

**Q：`validate.js` 说「内容量不足 5000 字」？**
说明 `overview` / `method` / `data` / `conclusion` 基本没写。这一项拦的不是字数，
而是"有没有真读原文"。回去补内容，不要补废话。

**Q：能加第七个模块吗？**
不建议。模块的 `id`（`dash`/`landscape`/`map`/…/`session`）已被 `app.core.js` 的标题映射、
`app.bind.js` 的导航绑定、以及全组的对比习惯所依赖。确有特殊需求，用 `views` 里加 `"extra": true` 挂到导航末尾，
但要知道这样你的产出就和别人不一样了。

**Q：数据里有 380 篇，页面会不会卡？**
不会。500 篇以内渲染在 1 秒内。真正要注意的是"篇数对不对"——
`papers.json` 的条数必须等于你数据文件夹里的论文数，去重合并的要记进 `mergedIds`。
数字对不上是最容易被导师抓到的错。

**Q：能多人一起做同一份吗？**
各人做各自方向的项目（各自的 `config.json` + `papers.json`），共用一个 `assets/`，
产出天然同格式。合并时只合 `papers.json`，重跑一次 build 即可。
注意 `lsKey` 每个项目必须不同，否则同一台电脑上打开两个工作台会互相覆盖笔记。

**Q：`pdf2md.py` 报「空壳 / 乱码 / 分栏错乱」并退出码 2，是不是坏了？**
没坏，是它在拦你。四类情况的处置不一样，别混着记：

- **PDF 没有文字层**（扫描件／只放了一张图的占位文件）与 **解析异常** → 直接拦下：不写 md、退出码 2。
- **抽出来全是 `�`**（字体编码异常）与 **双栏左右栏被交错拼成一句** → 只打 `[警告]`，**md 照样写**，退出码仍是 0。

后两种只能靠人读一段判断。四类的 md 一旦进 `papers.json`，后面的饼图和"未抽到数据集"统计都会错。
先 `--check-only` 看一眼再决定：真需要 OCR 就补 OCR；确认是占位文件就把它从库里剔掉并在
`meta.json` 的 `review` 里记一条；实在要硬写，加 `--write-anyway`，但请自己承担后果。
分两次（比如按年份）跑不会互相覆盖了 —— `manifest.json` 现在按文件合并。

**Q：改了 `papers.json` 后，点「导出笔记」没反应，其他都正常？**
先看构建时的 `[数据质量]` 提示和 `validate.js` 的第 30 项。最常见原因是
`datasets` / `metrics` / `stages` 被写成了字符串而不是数组 —— 页面显示没影响，
但导出笔记里要 `join('、')`，字符串没有这个方法，异常被浏览器的事件机制吞掉，
表现就是"点了没反应、也没有报错"。改成数组即可（`["RMSE", "PSNR"]`）。

**Q：`config.bands` 的阈值该填多少？**
不要拍脑袋。`landscape.py` 跑完会打印按本批分数分位数算的建议值
（核心 ≥ P90、高度 ≥ P70、中度 ≥ P45、间接 ≥ P20）。分数改过之后一定要重定，
改完分数记得重跑一次，不然旧阈值配新分数，条形图的档位分会和总分打架。
（`validate.js` 遇到这种情况只给"提醒"不判错 —— 档位允许人工勾，不一定是按分数机械换算的。）

**Q：配置文件存成 UTF-8 带 BOM 了，会怎样？**
V4.6 之后不会崩了：所有脚本都用 `utf-8-sig` 读。但对方用的是旧版本时仍会报
`Unexpected UTF-8 BOM`，所以传给别人的数据最好存成**无 BOM 的 UTF-8**。

### 只用基础六页，还是连 V3 / V4 一起用？

| 你的情况 | 要跑什么 |
|---|---|
| 只想把一批文献整理成看板 | `build.py` → `validate.js` |
| 还想知道"这批文献说明了什么" | 加 `landscape.py` |
| 还想找选题、看哪条路值得走 | 加 `directions.json`（手写）+ `link.py` |
| 还想补检本库之外的文献 | 加 `discover.py`（需要联网） |

不影响其他页面使用。

它是一个**辅助学习模块**（把方向拆成可执行模块、给算法讲四级解释、列失败案例与练习题），
**仍在开发中**，生成内容**耗额度较多**。只想要一份文献工作台去读、去标注、去导出笔记的话，
这一页是纯负担 —— 所以默认不启用，改成由你选。

要用的话，三种方式任选其一：

```bash
# ① 命令行加参数
python scripts/build.py <你的项目目录> --with-lab
```
```json
// ② 或者在 config.json 里写
{ "features": { "lab": true } }
```
```json
// ③ 或者在 config.views 里手写 lab 这一项
```

提示告诉你"有这个东西、怎么开"。

**要不要做？** 满足任一条就值得：你要发论文或做毕设，需要说清"为什么用这个方法"；
项目里有多个可选方案且各有前提；你问过"我这步做得对不对""为什么效果不好"。
只是想把文献摊开看一眼的话，不必做。

### 想知道这一版和上一版差在哪？

打开包里的 **`变更记录.md`**（CHANGELOG.md）。每次改动 Skill 都会往里追加一行，
写清楚「改了什么 / 为什么改」。发给别人之前先扫一眼这个文件最省事。

### 想查这批论文到底有没有开源代码？

```bash
python scripts/check_code.py <你的项目目录>
```

它会逐篇去 OpenAlex 匹配标题、还原摘要，只认**出版方明写的 github 地址**（摘要或
开放获取落地页里出现的），找不到就标成"未提及"，不猜。跑完把 `data/code_check.json`
里的结果并进 `papers.json` 的 `hasCode` / `codeUrl` 字段即可。

⚠️ 这个字段最容易被"凭印象填"污染 —— 记不清就填 true，或者干脆全填 false，
让页面显示"174 篇都没有开源代码"。两个都是坏答案：前者是假的，后者会让读者
以为这个领域没人开源。
