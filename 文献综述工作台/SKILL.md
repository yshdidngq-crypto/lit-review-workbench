## 0. 这份文件怎么用

**方式 A（推荐，一次装好长期可用）**
把整个 `文献综述工作台/` 文件夹放进 `~/.workbuddy/skills/`（Windows 即 `C:\Users\<用户名>\.workbuddy\skills\`），
之后任何新对话里说"帮我整理这批文献"就会自动触发。

**方式 B（临时用一次）**
新开一个 WorkBuddy 对话，把本文件全文粘贴进去，末尾附上你的三句话需求（见第 2 节）。

> 两种方式产出完全一致。原因见第 1 节。

## 1. 为什么换台电脑、换个人，产出还能一模一样

WorkBuddy 会读取每个用户的个人偏好（称呼、语气、审美倾向、常用库）。如果是"你描述外观 → 模型自由发挥"，
那每个人做出来一定不一样：颜色深浅、卡片圆角、图表留白、字体都会漂。

所以本规范把外观**从提示词里拿走，放进实体文件**：

| 层 | 文件 | 谁负责 | 能否改 |
|---|---|---|---|
| 视觉层 | `assets/base.css`（样式基线） | 锁死 | **禁止修改** |
| | `assets/charts.js`（SVG 图表引擎） | 锁死 | **禁止修改** |
| | `assets/ui.js`（卡片/表格/KPI 构件工厂） | 锁死 | **禁止修改** |
| | `assets/index.tpl.html`（页面骨架） | 锁死 | **禁止修改** |
| | `assets/app.core.js`（状态/筛选/排序/路由） | 锁死 | **禁止修改** |
| | `assets/app.bind.js`（事件绑定） | 锁死 | **禁止修改** |
| | `assets/views.base.js`（通用骨架视图，V4.8） | 锁死 | **禁止修改** |
| 数据层 | `config.json` + `data/papers.json` | 每个项目自己写 | 必须写 |
| | `data/directions.json` + `data/external.json`（V3 可选） | 每个项目自己写 | 用了新模块才要写 |
| 内容层（可选） | `src/views.js` + `src/tabs.js` | 每个项目自己写 | **可以不写**：用通用骨架；写了就覆盖同名项 |

`scripts/build.py` 构建时**只从 Skill 自己的 `assets/` 读这几个锁死文件**，不会读你项目目录里的同名文件。
所以哪怕有人手贱复制了一份 `base.css` 放自己项目里改，也不会生效。

而 `scripts/validate.js` 是客观门禁：它逐项比对颜色变量、字体栈、骨架类名、脚本注入顺序、数据完整性。
**不过校验就等于格式已经跑偏**，不许交付。

> 一句话记住：**你不要"设计"页面，你要"填满"页面。**

### 1.1 不写一行代码，也能出整个工作台（V4.8 起）

`assets/views.base.js` 是给全部十个内置页面写好的**通用版**：仪表板、研究现状、技术图谱、
方向探索、外部文献、文献数据库、文献对比、学习决策中心、阅读进度、检索记录，
外加九个详情标签。它只读 `config.json` 与 `data/`，不含任何项目特有的措辞。

所以最小可用项目只有两个文件：

```
我的项目/
├── config.json
└── data/papers.json
```

`python scripts/build.py 我的项目` 就能出一个完整页面，`validate.js` 与 `smoke.js` 照样能过。
构建时会打印这一版的内容层来源：

```
内容层：视图 10 个 —— 项目自己写 0 个，通用骨架 10 个（dash、landscape、…、session）
内容层：详情标签 10 个 —— 项目自己写 0 个，通用骨架 10 个
```

**什么时候该写 `src/views.js`：** 通用版的每个页面只回答"这批数据是什么样"，
不会替你说项目特有的话（空白点在哪、为什么这几篇最该先读、你的实验该怎么排）。
要这些，就在 `src/views.js` 里单独覆盖对应的那一个视图 —— 只覆盖一个，其余九个照旧用通用版：

```js
window.VIEWS = {
  dash: function (papers, cfg) { return '……你自己的仪表板……'; },
};
```

`window.VIEWS` / `window.TABS` 用 `Object.assign` 与通用骨架合并，**不需要把十个页面抄一遍**。
实测参考：`demo/` 自己写了 1,240 行 views.js 覆盖全部十页；`examples/data_only/` 一行没写，
两道门禁同样全绿 —— 差别只在页面上有没有"你的判断"，不在格式。

## 2. 开工前必须拿到的三样东西

用户只需要给你三句话，缺哪句就问哪句，不要猜：

1. **项目是什么** —— 研究方向 + 一句话目标（例："UAV 红外-可见光配准融合，做建筑缺陷检测"）
2. **当前需求是什么** —— 这批文献要拿来干什么（例："找出还没读的核心方法""给开题报告排阅读顺序"）
3. **论文数据文件夹在哪** —— 绝对路径

第三样是硬门槛。**没有数据就不许开工**，不许用"示例数据"占位、不许编造论文。
如果用户只给了一个文件夹但里面是 PDF，先做抽取（PDF 需先转文本）；如果是组里既有的精读 HTML 汇编，
直接解析其中的结构化内容（通常每篇含标题/作者/年份/出处/摘要/方法/结论）。

开工前顺手确认环境（一条命令，失败再说）：

```bash
python --version && node --version
```
Windows 上 `python` 不通就试 `py -3`；macOS/Linux 试 `python3`。
`node` 只用于跑校验，没有也能构建，但**校验是强制步骤**，请让用户装 Node。

## 3. 八步流程（顺序不可跳）

### Step 1　通读数据，先建"事实表"

不要先想页面长什么样。先把每篇论文读成一行结构化事实：

`id / 标题 / 作者 / 单位 / 年份 / 出处 / 关键词 / 研究问题 / 方法 / 数据与实验 / 结论 / 局限`

- 一篇都不许漏，也不许把两篇不同的论文合成一条（除非标题+作者+年份三项全同，才视为重复，并把被合并的编号记进 `mergedIds`）。
- 读不出来的字段写 `"未报告"` 或 `"无"`，**绝不写 `undefined`、空白、`暂无`**。
- 数字必须来自原文。指标、数据集名、对比方法名，原文没写就不写。

> 这一步做扎实，后面全是机械劳动；这一步偷懒，后面所有图表都是假的。

### Step 2　设计分类体系（本项目最重要的一次判断）

两个维度，都要从数据里长出来，不要套模板：

**（A）一级主题 `topics`** —— 回答"这批文献分几派"。4–8 类为宜，要求：
- 互斥：每篇只归一类（`topic` 单值）
- 有区分度：最大类不超过总数 45%，否则说明切得太粗
- 有颜色：每类一个 `color`，**必须从下面这套里取**，不许自己调色
  `#2f6feb` `#0e9c9c` `#c0392b` `#d97706` `#6b4bbd` `#8d9db2` `#c47b12`
- 最后一类留给"综述与外围"，避免弱相关文献污染主干

**（B）技术环节 `stages`** —— 回答"我的研究流程分几步，每篇能填哪一步"。
按**用户项目的实际流水线**切（例：配准项目 = 预处理→特征提取→匹配→变换求解→融合→评价→下游）。
6–12 个。每篇可属多个 stage（`stages` 数组）。这一步直接决定"技术图谱"页能不能看出空白点。

### Step 3　写 `config.json`

完整字段见 `references/03_配置说明.md`，最小可用骨架见 `examples/config.example.json`。
必填三项：`project` / `topics` / `views`。

`views` 共 10 个，**`id` 必须一致，不要改名**。前 6 个是必做，后 4 个是 V3 模块（数据没准备就保留空态，不要从 config 里删）：

| id | 名称 | 干什么 | 必做 |
|---|---|---|---|
| `dash` | 总览仪表板 | 整体形状、主题构成、年份分布、关键结论 | ✓ |
| `map` | 技术图谱 | 环节覆盖：哪步有方法、哪步是空白 | ✓ |
| `db` | 文献数据库 | 筛选、排序、逐篇查阅 | ✓ |
| `cmp` | 文献对比 | 2–4 篇横向对照 | ✓ |
| `decide` | 学习决策中心 | 先读哪篇、什么顺序 | ✓ |
| `prog` | 阅读进度 | 状态、笔记、备份 | ✓ |
| `landscape` | 研究现状 | 八个问题的数据答案 | V3 |
| `explore` | 方向探索 | 方向树、选题机会、方向对比 | V3 |
| `external` | 外部文献 | 补检清单、六维评分、BibTeX/RIS 导出 | V3 |
| `session` | 检索记录 | 查询词、数据源成败、排除原因 | V3 |

顺序按上表（`dash` 在前，`session` 在末）。**不要随意调换**：读者是按"先看全局 → 再看缺口 → 再看机会 → 再补文献"的顺序读的。

另外两个必给的：
- `bands`：评分档位 5 档，每档带 `name` / `color` / `action`。但 **`min` 必须按你自己 `relevance` 的分位数重定**——
  85/70/50/30/0 只是常见起点；若全批最高只有 64 分还照抄，总览页「核心相关」会恒为 0 篇、
  主预设点下去是空表，页面看着像坏了。`demo/` 就是因为样本最高 64 分而改成 60/45/35/28/0，
  原因写在 `demo/README.md`。判据：最高档、最低档都不该为空，中间三档大致均匀。
- `presets`：3–5 个一键筛选（`core` 必读、`unread-core` 高相关未读、`classic` 传统方法、`easy` 入门），
  阈值同样跟着 `bands` 走，定完要自己点一遍确认不是空表。

### Step 4　生成 `data/papers.json`

字段契约见 `references/01_数据契约.md`。**六个必填字段一个字都不能少**：

```json
{ "id": "E001", "title": "…", "topic": "T1",
  "relevance": 88, "learning": 75, "difficulty": 3 }
```

其余字段（`overview` / `method` / `data` / `conclusion` / `year` / `venue` / `stages` /
`extraScores` / `extraTags` / `datasets` / `metrics` / `hasCode`）能填就填——
**它们直接决定详情页有没有内容可看**。详情页空着，整个工作台就只剩一堆图。

评分口径（三档，0–100 / 1–5）：
- `relevance` 与用户"当前项目"的耦合度：是否同一任务、同一模态、同一场景、能否直接借用方法
- `learning` 学习价值：方法是否可迁移、是否经典必读、是否提供可复现代码/数据
- `difficulty` 阅读难度：1–5，1 = 综述级入门，5 = 需要强数学/工程前置
> 评分必须逐篇给理由，理由写进 `relevanceBreakdown` 或详情页文字。不许一把 85 分刷过去。

**同一趟里把「解析期发现的问题」记下来**，写进 `data/meta.json` 的 `review`。这一步不能省：
你在抽数据时一定会遇到「这条标题明显有毛病」「这个作者名多了个字母」「这条和那条像同一篇」，
如果只是自己绕过去、不记下来，用户就永远不知道库里哪些条目不能直接引用。

```json
{ "id": "R01", "paperId": "E276", "field": "title",
  "problem": "标题开头重复「基于基于」，中英文术语乱序插入，不构成通顺语序。",
  "basis": "源文件标题原文", "fix": "基于变分自编码器与红外特征补偿的…" }
```

- `field` 只能是 `title` / `author` / `year` / `venue` / `doi` / `body` / `duplicate` / `missing` / `pdf`
- `problem` **必填**，写「哪里不对」，不写「建议关注」。用户要能照着这句话去核对
- `basis` 写依据（跟哪个来源比出来的）。**说不出依据就不要下这条结论**——这可能只是你的猜测
- `fix` 只显示不自动应用：改数据必须经过人
- `id` 要稳定唯一（`R01`/`R02`…）。用户点「确认」后状态按它记在浏览器里，换成随机值会全丢
- 一条问题写一条，不要合并成「若干篇存在标题问题」——那就退回到笼统统计了，等于没写

### Step 4B　研究现状与外部补检（V3，推荐做）

三步，顺序不可颠倒：

```bash
# ① 由本库算出研究现状八问（纯本地，不联网）
python scripts/landscape.py <你的项目目录>

# ② 外部补检。检索词要你自己按子方向生成，3–6 组
python scripts/discover.py <你的项目目录> \
  --en "uav multimodal image registration thermal visible" \
  --en "facade crack detection unmanned aerial vehicle thermography" \
  --platform "uav drone aerial" \
  --object "building facade concrete crack" \
  --scenario "building facade crack detection" \
  --modality "infrared thermal visible"
```

③ 写 `data/directions.json`（方向树，字段见 `references/07_方向与关联.md`），然后：

```bash
python scripts/link.py <你的项目目录>
```

`link.py` 会把方向和外部文献双向挂起来，并算出机会分。**写完 directions.json 之后必然要重跑它**，
否则页面两侧的关联数对不上。

三条最容易犯的错：

- **拿"本库没有"当"学术空白"。** 本库只有几十篇，没有某主题只能说明你没收到。必须先用
  `discover.py` 看外部有没有人做，再写 `whyOpportunity`。
- **检索词只给一条大而全的英文句子。** 召回会很低（实测：2 组词捞到 161 条原始命中，过滤后只剩 19 篇；
  6 组词捞到 505 条，最终 29 篇）。按子方向拆词。
- **`--object` 用了 `structure` 这类泛词。** 它会匹配 `structural similarity`、`infrastructure`，等于没筛。

## 4. 二十条铁律（违反即返工）

**前五条管格式，第 6–12 条管结论，第 13–20 条管「话该怎么说、标签怎么给、公式怎么写、读者写的东西怎么拿走、模板别夹带私货、颜色别丢」。** 格式错了肉眼可见，结论错了没人能发现——
所以第 6 条之后每一条都要求你在写之前先确认「我凭什么这么说」。

第 13 条的具体执行方式（最容易被忽略，也最伤专业感）：

第 14 条的具体执行方式（V4.2 新增，V4.4 补吸附要求）：

- **位置**：同一屏最上方，在图表之前。不要写在图注、表格末尾或页脚——读者第一次看到 `S7`

- **不许截断**：`.sidmap-i span` 上不加 `text-overflow:ellipsis`。「数据准备与跨模态预…」

第 16 条的具体执行方式（V4.4 新增）：

- **写法**：行内用 `$…$`，独立成行用 `$$…$$`。多行推导用 `$$\begin{aligned}…\end{aligned}$$`，
  每行末尾 `\\`，对齐点写 `&`。矩阵用 `\begin{bmatrix}`，范数用 `\lVert h\rVert`，
  转置用 `^\top`，函数名用 `\mathrm{PC}(x)`（否则会排成 P·C 斜体乘积）。
- **不许硬拼**：`x′`、`σ²`、`√`、`∑`、`≤`、`→` 这些字符在换字体时对不齐基线，
  而且 Unicode 上下标只有很少几个字，终究写不出 `H^{-1}`、`\hat{x}`、`\tilde{p}`。一律走 LaTeX。
- **不许裸露**：页面上出现 `\frac`、`\mathrm`、`$$` 字样就是渲染失败的证据，见到即返工。
- **为什么必须在字符串层切分**：`ui.js` 的 `rich()` 先切公式再 `esc` + 换行转 `<br>`。
  如果先把 `\n` 变成 `<br>`，`$$…$$` 就被拆进多个文本节点，DOM 层的补救脚本再也匹配不到，
  页面就会把 TeX 源码原样摊出来。这是 V4.3 的真实 bug，已修，别再改回去。
- **离线**：KaTeX 已全量内联（`assets/katex.min.js` + 字体 base64 写进 `katex.css`），
  不许改成 CDN 引入——那会直接违反「离线自包含」这一项。

第 17 条的具体执行方式：见上面第 14 条的「必须跟随」——两条说的是同一件事，
区别是第 14 条管**有没有对照**，第 17 条管**对照跟不跟着滚动**。

第 18 条的具体执行方式（V4.5 新增）：

### 4.1 反面清单：这些写法一律不要

「不编造」「不要旁白」这种要求，说了等于没说 —— 谁都觉得自己没在编。
好用的禁令必须**点名病灶长什么样**。下面每一条都是真实出现过的写法，
看到就删，别解释。

- **给每篇写一段摘要。** 24 篇就是 24 段互不相干的文字，读者还得自己比。这是最常见、
  也最像"没做完"的失败：信息全在，结论为零。要么给对比表的一列，要么不给。
- **用"首先/然后/最后"串流程。** 「本文首先介绍了……然后提出了……最后验证了……」——
  这是复述结构，不是内容。删掉这三个词，句子还在，说明本来就该删。
- **效果写形容词。** 「效果良好」「性能优越」「显著提升」——没有数字、没有对照方法、
  没有数据集，等于什么都没说。要么写具体数字，要么写"未报告定量结果"。
- **把摘要级判断写成全文结论。** 外部文献你只看过摘要，就只能写"摘要称……"。
  写成"本文证明了……"，是把别人的谨慎变成了你的胆量。
- **拿"本库没有"当"没人做过"。** 只能说"本次检索未发现"。这两句话差着一个量级。
- **给方向配形容词而不是问题。** 「多模态融合方向很有前景」是空话；
  「弱对齐场景下 RGB-T 的几何配准误差能否压到 3 像素内」才是方向。
- **把施工期信息留在页面上。** 版本号、TODO、"待补"、脚本名、"本页由 X 生成"——
  这些是给开发者看的，不是给导师看的。
- **自我评价。** 「本页数据翔实，可支撑选题决策」——页面不夸自己。

## 6. 已知坑（新人必踩）

**坑 1：页面全白，控制台 `VIEWS is not defined` 或视图区一片空**
→ 你没在 `views.js` 里写 `window.VIEWS = window.VIEWS || {};`，或写成了 `const VIEWS = {}`。
必须是挂到 `window` 上。

**坑 2：点卡片、点图例没反应**
→ 你写了 `onclick=` 或 `addEventListener`。改成 `data-*` 属性，由 `app.bind.js` 接管。
可用的只有这几个，别自己发明：

| 写法 | 作用 |
|---|---|
| `data-act="open" data-val="论文ID"` | 打开详情抽屉（图表元素、表格行都用这个；外部文献同样走它） |
| `data-act="nav" data-val="视图ID"` | 切视图 |
| `data-act="topic" / "stage" / "year" / "status" / "band"` + `data-val` | 按该维度筛选 |
| `data-act="tag" data-dim="platform" data-val="UAV无人机"` | 按额外标签维度筛选 |
| `data-act="clear"` | 清空全部筛选 |
| `data-chip="dl" data-val="传统方法"` | 多选切换（方法类型等） |
| `data-preset="预设ID"` / `data-sort="排序键"` / `data-mode="cards\|table"` / `data-page="2"` | 预设 / 排序 / 列表形态 / 翻页 |
| `data-dtab="标签ID"` | 详情抽屉切标签 |
| `data-f="q\|relMin\|learnMin\|diffMin\|diffMax"` | 表单字段绑定 |
| `data-act="dir-open" data-val="方向ID"` | 选中方向并跳到方向探索页（V3） |
| `data-act="state" data-k="状态键" data-val="值"` | 直接写 `S[状态键]`（V3）。加 `data-toggle="1"` 为开关，加 `data-clear="1"` 为置空 |
| `data-act="obj-set" data-k="labStat" data-id="M3" data-val="进行中"` | 写**对象**的某个键（V4）。`data-toggle="1"` 为数组开关，`data-clear="1"` 置空数组 |
| `data-save-store="labDiag" data-store-id="d"` | 把文本框内容存进对象键（V4）。**不带 `data-then-render` 时不重渲染**，避免输入时光标丢焦点；带 `data-then-render="1"` 才刷新（逆向诊断这类「点了按钮才出结果」的场景用） |

最后那条 `state` 是刻意留的通用口子：V3 的筛选维度（`dirSort` / `extAccess` / `extDir` /
`dirCmp` / `dirFav`）都走它，不必每加一个维度就往 `app.bind.js` 里塞一个 `if`。

主题切换用固定 id `#themeBtn`，不要自己造。


本包不含实验室，这两条不再适用，编号留空（后续编号不变，免得旧笔记对不上）。

**坑 5：`undefined` 或 `NaN` 出现在页面文字里**
→ 字段名拼错，或某篇确实没这个字段。取值一律走 `p.xxx || ''`，或直接用 `dash(v)` / `fmt(n)` 兜底。
`validate.js` 的「渲染值」项查两处：数据字符串里有没有 `undefined`/`NaN`，以及产出 HTML 正文里
`undefined`/`NaN` 前后 8 个字符内有没有中文（有中文说明它漏进了给人看的文字里）；
`smoke.js` 再把 11 个视图、10 个详情标签、13 个交互分支全跑一遍，检查运行时拼出来的结果。
静态扫不到的、只有运行时才拼出来的泄漏，靠 smoke 那一层。

**坑 6（V3）：方向树画出来了，但所有外部文献都挂不上方向**
→ `directions.json` 的 `keywords` 只写了中文。外部文献是英文库返回的，中文方向名一个词都匹配不上。
每个方向至少给 3 个英文关键词，然后**重跑 `link.py`**（改完 directions 不重跑，页面两侧数字必然对不上）。

**坑 7（V3）：方向挂上太多文献，一篇综述同时属于六个方向**
→ `--min-overlap` 太小，或把 `problem`/`whyOpportunity` 也拿去匹配了。方向的身份只能由
「名称 + 一句话 + 关键词」决定，几百字的论证散文里全是领域词，会让每个方向命中几乎所有文献。

**坑 8（V3）：外部文献点开详情，标签一片"—"**
→ 你只写了 `detailTabs` 那套（`understand`/`eval`…），外部文献没有 `overview`/`method` 字段。
补 `extTabs` 那套（`extAbs`/`extWhere`/`extDir`/`notes`），`app.core.js` 会按 `kind` 自动切换。

**坑 9（V3）：`landscape.py` 说"前五名占一半，高度分散"**
→ 这是它早期版本的真 bug，已修。HHI 的绝对值不能直接定性，必须除以均匀基准（`1/来源数`）再判断。
如果你自己写类似的集中度分析，注意同一个问题。

**坑 10（V3）：门禁全绿，页面还是错的**
→ `validate.js` 查的是数据与格式，`smoke.js` 查的是"渲染不报错、不出现 NaN"，**都看不见版式错误**。
真机上最常见的四类，逐条自查：

| 症状 | 成因 | 改法 |
|---|---|---|
| 少了一整个维度（如六维只剩五维） | 把"总分"当成第 7 格塞进六维网格，多出的一格被挤到网格外 | 总分单独放 `.etot` 徽标，网格只放真维度 |
| 英文标题切成 `…Analysis o` | 用 `title.slice(0,78)` 截字符串 | 用 `.clamp2` 交给浏览器按行裁，或 `clip()` 停在词边界并补「…」 |
| KPI 卡末行空两格 | 5 张卡配 `grid(4)`，或断点刚好落在窗口宽度上 | `grid(n)` 的 n 与卡片数一致；断点留足余量 |
| 一块说明文字出现两遍 | SVG 里画了图例，`chartBox` 的 caption 又写了一遍 | 图例只留一处 |

→ 验证办法：用系统 Edge 无头模式逐页真机截图，绕过 SPA 默认只渲染首页的限制：

```bash
# 把 dist 的 HTML 复制一份，在 </body> 前注入一段读 ?view= / ?dir= 的脚本
# 再对每个状态截一张，最后逐张看
msedge --headless=new --disable-gpu --hide-scrollbars --window-size=1500,3000 \
       --virtual-time-budget=6000 --screenshot=out.png "file:///…/_probe.html?view=explore"
```

**坑 11（V4.1）：点年份条形，页面变成「没有文献」**
→ 条形上显示的是给人看的标签 `2025 年`，而你把它直接当筛选值传了出去；
`filtered()` 里比较的是 `String(p.year)` 即 `2025`，两边永远不相等。

```js
// 错：标签与筛选值混成一个字段
yearItems = years.map(y => ({ k: y + ' 年', v: cnt }));          // data-val 变成 "2025 年"
// 对：显示与取值分开，chartHBars 优先取 val
yearItems = years.map(y => ({ k: y + ' 年', val: y, v: cnt }));
```

`chartDonut` 早就是这么做的（`it.code`），`chartHBars` 从 V4.1 起才补上 `it.val`。
**凡是要点的元素，`k` 只负责好看，`val`/`code` 负责能对上号。**

这类错误两道门禁都查不出来：静态 HTML 里是运行时渲染的，根本没有那个字符串；
`smoke.js` 只点不存在的桩。只有真机点一次才知道。验证办法：

```bash
node scripts/test_click.js "demo/dist/xxx.html" year 3
# 派发真实 click → 打印 filters.year 与筛选后的篇数；第三参数可断言期望篇数
```

窗口高度要给够（长页 3200 起步，`landscape` 约 3300 才不被截断）；
截图后务必放大看细节——上面四个问题在全页缩略图里都"看起来正常"。
