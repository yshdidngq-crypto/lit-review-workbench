文献综述工作台 · 使用说明
==================================================

这是一个给 WorkBuddy 用的"技能包"，作用是：
把你手上的文献整理成一份统一的、可以离线打开的单文件 HTML 工作台。

--------------------------------------------------
怎么用（二选一）
--------------------------------------------------

【方式一 · 只用一次】
1. 打开 文献综述工作台\SKILL.md
2. 全选、复制
3. 在 WorkBuddy 新开一个对话，粘贴进去
4. 紧接着写三句话：
      我的项目是：……（研究方向 + 一句话目标）
      现在的需求是：……（这批文献要拿来干什么）
      论文数据文件夹：D:\……（绝对路径）
5. 等它做完

【方式二 · 装一次长期可用】
把 文献综述工作台 这个文件夹，整个复制到
      C:\Users\<你的用户名>\.workbuddy\skills\
然后重启 WorkBuddy。以后新对话里说"帮我整理这批文献"就会自动触发。

--------------------------------------------------
动手之前先确认两件事
--------------------------------------------------
1. 装了 Python 3.8 以上：命令行敲  python --version
2. 装了 Node.js 14 以上：命令行敲  node --version
   （不需要 pip install，也不需要 npm install，脚本零依赖）

--------------------------------------------------
先跑一遍例子，确认环境没问题
--------------------------------------------------
在 文献综述工作台 目录下执行：

    python scripts/build.py demo
    node scripts/validate.js  "demo/dist/RGBFusion_文献工作台.html"
    node scripts/smoke.js     "demo/dist/RGBFusion_文献工作台.html"
    node scripts/test_click.js "demo/dist/RGBFusion_文献工作台.html" year

看到"结果：通过（30 项检查全绿）"、"结果：全部通过"和"✓ 筛选生效"就说明环境 OK。
第一个查格式与数据，第二个把十一个页面渲染一遍查报错和空值，
第三个真的在浏览器里点一下年份条形，确认点了能筛出文献。
然后双击 demo\dist\RGBFusion_文献工作台.html，看看成品长什么样。
你自己项目的产出，除了内容不同，样式应该和它一模一样。

--------------------------------------------------
为什么换台电脑、换个人做出来也一样
--------------------------------------------------
assets 目录里的文件（base.css / katex.css / katex.min.js / math.css / math.js /
charts.js / ui.js / app.core.js / app.bind.js / lab.js）是锁死的，构建脚本只从技能包自己的 assets 读，
不读你项目里的同名文件。所以不管谁的 WorkBuddy、什么个人偏好，
出来的页面都是同一套配色、同一套卡片、同一套图表。

validate.js 是配套的格式门禁，30 项检查（颜色变量、字体栈、骨架结构、
离线自包含、脚本注入顺序、数据完整性、方向树、外部文献、双向关联、现状报告、
模块拆解、实验室引用、学习单元、实验与失败、决策题……）。
smoke.js 是渲染门禁，把 11 个页面、10 个详情标签、13 个交互分支、1 条编号对照块各跑一遍。
test_click.js 是交互门禁，真机点一下年份条形，确认点了真的筛得出文献。
三个都有 ✗ 就不许交付，修到全绿为止。

注意：这三道门禁都看不见"版式"错误（少一列、标题切成残词、格子空着）。
交付前务必自己在浏览器里翻一遍十一个页面。

V4.7.0 修了什么（建议先看这段）
--------------------------------------------------
· 工程实验室改成【用户自选】：不再因为 data/lab.json 存在就自动加进侧栏。
  启用方式三选一：命令行 --with-lab、config.json 里 "features": {"lab": true}、
  或在 config.views 里手写 lab；都不写就不启用，构建时会提示怎么开。

· 分类色不再丢：主题没写 color 时，环形图与散点气泡会退化成同一种灰，分类维度
  整个消失。锁定层新增默认色板兜底，并新增门禁要求 config.topics 每项都带颜色。
· 热力矩阵表头不再被裁：分类全名过长会撑破卡片右边界，改为限宽换行。
· 待审核数据不再永远为空：抽取阶段的问题逐条落盘，并按字段分组折叠展示。
· 数据集与开源代码不再空：修了"无人机"被当成空值前缀误杀的 bug，
  数据集只收有专名的；新增 check_code.py 走 OpenAlex 找出版方明写的 github 地址。
· 新增 变更记录.md（CHANGELOG.md）：每次改动都追加一行，发给别人时对方能一眼
  看出这版和上一版差在哪。

V4.3 修了什么
--------------------------------------------------
· 修掉「工程实验室 → 建模与算法决策」的崩溃（页面显示「渲染失败 L is not
  defined」）。选中一个没有候选算法的模块（如「系统集成与数据检查」）就必崩，
  原因是那段代码引用了一个没有声明的变量。冒烟门禁补上了这条分支，
  以后再犯会被直接拦住。
· 方向树的「枝粗」原来根本看不出差别：机会分落在 50–85，换算成线宽只有
  4–6 像素，全部一样粗。现在按本批最高/最低分做归一化，映射到 2–11 像素，
  最粗最细一眼能分。图注也写清「本批内相对」，免得读成满分。
· 树枝原来只有 12 像素长（两列挨得太近），现在拉开到 64 像素，粗细才有地方显示。
· 节点加了编号：左列 1、2、3，右列 1.1、1.2…… 树里到底几个方向，不用数方框。
  （父方向写错的节点以前会静默消失，现在补画出来。）
· 「阶段」「基础」这类标签不再写死在模板里。这个 Skill 是给很多项目、很多人
  复用的，模板写死某一种叙述，别人用起来像借了别人的本子。现在统一由
  data/lab.json 的 profile.facts 提供：填几条显示几条，不填就整排不显示。
  老数据用 scripts/migrate_facts.py 一条命令迁移。

V4 多了什么
--------------------------------------------------
· 工程实验室：一个新的侧栏菜单，里面五个标签页 ——
  ① 项目拆解地图：把研究方向拆成六层、十来个模块，画出依赖图，标出每步的

     以及失败模式库 —— 你描述现象，它按关键词给出候选假设与区分测试
     （明确说明这是规则匹配，不是诊断结论）。
  ⑤ 交互式科研训练：三种模式（引导 / 参考 / 挑战）的决策题，掌握度六档
     由你自己确认，绝不按浏览行为自动升级。
· 这一页要你自己写一份 data/lab.json；没有这份文件的项目不会出现这个菜单，
  所有旧项目照常可用。
· 两个可直接运行的验证案例：examples/lab_canny（Canny 边缘检测）、
  examples/lab_uav3d（无人机三维重建，含 P3P 误用防护）。
